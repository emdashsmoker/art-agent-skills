# 로컬 모델을 활용한 이미지 생성

이 스킬은 로컬 모델로 이미지를 생성하고 모델이 낸 결과를 그대로 전달한다. 모델 파일은 스킬을 실행하는 환경(실행 환경)에 내려받고 생성은 실행 환경의 CPU에서 수행한다. 네트워크는 패키지와 모델 파일을 내려받을 때만 사용한다. 프롬프트는 외부 이미지 생성 서비스로 전송하지 않는다. 결과물은 PNG 또는 JPEG 파일이다.

확산모델은 글자, 정확한 연결선, 수치, 정확한 개수를 표현하지 못한다. 이러한 요소가 필요한 요청은 전달하려는 의미를 사물이나 장면으로 치환해 그린다. 글자는 완성된 이미지 위에 편집 도구로 추가한다.

## 작업 순서

1. 환경 준비: 스킬 전용 가상환경을 생성하고 의존성을 설치한다.
2. 요청 분류와 구도: 그릴 대상과 구도를 정한다. 화풍을 지정하지 않은 요청은 추천 화풍을 정한다.
3. 생성 전 질의: 모델 선택과 선택 기능을 한 번에 질의한다. 자동으로 답한 항목은 값을 정해 안내한다.
4. 프롬프트: 영문 프롬프트를 작성한다.
5. 생성: generate.py를 실행한다.
6. 선별과 재생성: 후보 배수가 2배 이상이거나 재생성 상한이 1회 이상인 경우에만 수행한다.
7. 전달: 파일과 재현 정보를 전달한다.

후보 배수가 1배이고 재생성 상한이 0회면 스크립트의 기계 점검(파일 크기, 형식, 픽셀 크기)을 거친 파일을 바로 전달한다.

## 명령 표기

- `PY`는 스킬 전용 가상환경의 파이썬이다. 리눅스와 macOS는 `~/.cache/image-gen-lite/venv/bin/python`, 윈도우는 `%USERPROFILE%\.cache\image-gen-lite\venv\Scripts\python.exe`다.
- `scripts/`는 이 스킬 폴더 안의 scripts 폴더 경로로 대체해 사용한다.
- 명령은 사용자의 작업 폴더에서 실행한다. 결과 파일은 사용자가 지정한 경로에 저장한다. 지정한 경로가 없으면 실행 환경이 지정한 산출 폴더에 저장하고, 산출 폴더도 없으면 작업 폴더에 저장한 뒤 절대 경로를 안내한다.
- 스크립트는 리눅스, macOS, 윈도우에서 같은 명령으로 동작한다. 정밀 프리셋은 리눅스 x86_64, Apple Silicon macOS, 윈도우 x64에서 동작한다.
- 스킬이 내려받는 모든 파일은 캐시 폴더 `~/.cache/image-gen-lite`에 저장된다. 환경변수 `IMAGE_GEN_LITE_HOME`으로 위치를 변경할 수 있다.
- 정밀 프리셋 엔진은 GitHub(`leejet/stable-diffusion.cpp`)에서 내려받는다. 세션에 GitHub 저장소를 연결하는 도구가 실행 환경에 있으면 첫 실행 전에 해당 저장소를 대상으로 호출한다. 소유자와 저장소 이름은 `/` 앞뒤를 각각 별도로 전달한다.

## 환경 준비

패키지는 스킬 전용 가상환경 하나에만 설치한다. 사용자 환경에 이미 설치된 패키지는 삭제하거나 변경하지 않는다. GPU용 torch나 CUDA 패키지가 설치된 환경도 그대로 유지한다. 전용 환경에 CPU용 torch를 별도로 설치하므로 두 환경은 서로 영향을 주지 않는다.

```
python3 -m venv ~/.cache/image-gen-lite/venv
PY -m pip install --no-cache-dir torch torchvision --index-url https://download.pytorch.org/whl/cpu
PY -m pip install --no-cache-dir diffusers transformers accelerate safetensors peft huggingface_hub pillow numpy
```

- `python3`가 없으면 `python`으로 실행한다. 윈도우는 `%USERPROFILE%\.cache\image-gen-lite\venv` 경로에 생성한다.
- torchvision은 torch와 같은 CPU 인덱스에서 함께 설치한다. 다른 패키지가 CUDA용 torchvision을 끌어오면 `operator torchvision::nms does not exist` 오류가 발생한다.
- `--no-cache-dir`은 내려받은 설치 파일을 공용 pip 캐시에 보관하지 않는다.
- 가상환경을 생성할 수 없으면(venv 모듈 누락 등) 현재 파이썬 환경에 설치할지 사용자에게 질의한다. 허락을 받은 경우에만 해당 환경에 설치하고, externally-managed-environment 오류가 발생하면 `--break-system-packages`를 추가한다.
- pip 설치 권한이 없으면 생성할 수 없다. 이유를 안내하고 작업을 중단한다.
- 파이썬을 실행할 수 없는 환경도 생성할 수 없다. 이유를 설명하고, 영문 프롬프트와 프리셋 설정을 전달해 사용자가 파이썬을 사용할 수 있는 환경에서 생성하도록 안내한다.
- 가상환경이 이미 있으면 설치를 생략하고 `PY -c "import torch, diffusers"`로 확인만 한다.

## 요청 분류

생성 전에 요청을 아래 세 유형 중 하나로 분류한다. 분류 기준은 사용자가 그릴 대상을 구체적으로 지정했는지 여부다.

| 유형 | 판정 | 처리 |
|---|---|---|
| 지정 피사체 | 사물, 인물, 동물, 장소처럼 윤곽이 드러나는 대상을 사용자가 지정함 | 지정한 대상을 그대로 그린다 |
| 메시지 요청 | 추상 개념이나 전달하려는 메시지만 제시함 | 그릴 수 있는 사물이나 장면으로 치환한 구성을 생성 전 질의에서 확인받고 그린다 |
| 도해 요청 | 글자 라벨, 연결선, 정확한 개수, 수치가 필요함(흐름도, 개념도, 구조도, 차트, 지표 그림) | 한계와 대체안을 생성 전 질의에서 안내하고 동의를 받은 뒤 그린다 |

- 사용자가 상징성이 있는 사물을 지정했다면 이미 선택을 마친 결과이므로 변경하지 않는다.
- 사물과 메시지를 함께 제시하면 사물을 그리고, 메시지는 화풍과 색으로 반영한다.
- 치환은 메시지를 한 번만 사물이나 장면으로 바꾼다. 예: 성장은 새싹이 돋는 화분, 협력은 겹쳐 잡은 두 손, 보안은 닫힌 자물쇠, 속도는 질주하는 자전거, 연결은 다리로 이어진 두 섬.
- 치환안은 사용자가 떠올린 모습과 다를 수 있으므로 생성 전 질의의 치환 확인 항목에 치환안 1개와 대안 1개를 함께 제시한다. 사용자가 다른 사물을 답하면 그 사물을 그린다.
- 구도가 장면형이면 치환한 사물을 포함한 소재 2-3개에 시간대와 색 계열까지 묶어 장면으로 제시한다. 예: 팀워크의 장면형 치환안은 호수 위에서 함께 노를 젓는 조정 보트, 아침 햇살, 차분한 파랑 계열.
- 도해 요청의 안내 문안 예: "흐름도의 글자와 연결선은 확산모델이 정확히 그리지 못합니다. 단계를 상징하는 사물 3개를 나란히 배치한 그림으로 대신 생성할 수 있으며, 글자는 편집 도구에서 추가하시면 됩니다. 이렇게 진행할까요?"

## 미성년자 보호

미성년자의 노출과 성적 묘사(성행위 포함)는 생성하지 않는다.

- 미성년자는 18세 미만 나이나 미성년 신분을 명시한 인물, 이차성징 이전의 몸(아동의 머리 대 몸 비율과 체형)이 분명한 인물이다.
- 동안 얼굴, 큰 눈, 아이돌 같은 인상, 셀화, 작은 키, 마른 체형, 유행하는 옷차림 등 명시적이지 않은 모호한 신호나 문화적 취향은 미성년자 판단의 근거로 삼지 않는다.

## 구도

구도는 도상형과 장면형 두 가지다. 구도는 질의하지 않고 아래 순서로 정한다.

1. 사용자가 구도를 지정하면 그대로 따른다.
2. 사용자가 피사체를 둘러싼 배경(거리, 해변, 방 등)이나 시간대를 직접 묘사하면 장면형으로 생성한다. 묘사한 배경과 시간대를 장면의 소재와 시간대로 사용한다.
3. 사용처가 있으면 아래 표의 주 용도에 따라 정한다.
4. 사용처도 없으면 피사체를 가장 분명하게 보여주는 도상형으로 생성한다.

| 구도 | 모습 | 주 용도 | 프롬프트 순서 |
|---|---|---|---|
| 도상형 | 피사체를 화면 가운데에 배치하고 단색 배경을 사용함 | 본문 삽화, 장표 삽화, 사물 하나를 강조한 그림 | 피사체, 화풍, 색, `plain background` |
| 장면형 | 보편적인 소재 2-3개에 시간대 1개와 색 계열 1개를 추가함 | 배경 이미지, 배너, 표지, 간지, 슬라이드 배경, 풍경 그림 | 소재 조합, 시간대, 색, 화풍 |

- 장면형의 소재는 사용처의 주제에서 떠올릴 수 있는 보편적인 사물과 장소를 고른다. 예: 교육 자료의 배경은 책상 위의 책과 창가의 식물, 아침 햇살, 따뜻한 베이지 계열.
- 장면형의 시간대는 `morning light`, `golden hour`, `night`처럼 빛의 상태를 가리키는 표현으로 쓴다. 색 계열은 사용처의 자료에 이미 쓰인 색이 있으면 그 계열을 따른다.

## 화풍

사용자가 화풍을 지정하면 그대로 따른다. 지정하지 않으면 질의하지 않고 추천 화풍 1개를 정해 안내한다. 화풍을 지정하지 않는 요청이 많다. 화풍 질의는 처음 사용하는 사용자에게 답하기 어려운 질문이다.

- 추천 화풍은 요청의 분위기와 사용처에 어울리는 화풍을 기법 이름으로 정한다. 정할 근거가 없으면 디지털 페인팅으로 정한다.
- 추천 화풍은 프리셋 절의 모델별 특성에 맞춰 고른다. 예: 표준 모델은 플랫 벡터에서 형태가 무너지므로 플랫 벡터를 추천하지 않는다. 플랫 모델에는 플랫 벡터나 물감 번짐 수채화를 추천한다.
- 생성 전 질의에서 모델을 함께 고르면 기본값인 표준 모델 기준으로 안내한다. 답변으로 정해진 모델에 추천 화풍이 맞지 않으면 그 모델에 맞는 화풍으로 바꾼다. 바꾼 화풍은 생성 전에 한 줄로 안내한다.
- 생성 전 질의를 진행하면 질의 안에서 추천 화풍을 한 줄로 안내한다(질의 형식). 사용자가 답변에 다른 화풍을 적으면 그 화풍을 따른다.
- 질의 없이 생성하면 생성 전에 추천 화풍을 한 줄로 안내한다. 안내 후 확인을 받지 않고 진행한다.

## 프리셋

프리셋은 모델과 고정 설정의 조합이다. 화풍은 프롬프트로 변경하고, 모델은 프리셋으로 변경한다. 스텝 수, guidance, 스케줄러는 스크립트에 고정되어 있다. 값을 변경하면 형태가 뭉개지는 조합이 많으므로 기본값을 유지한다.

| 프리셋 | 역할 | 적합한 화풍 | 생성 크기 | 첫 내려받기 |
|---|---|---|---|---|
| `dreamshaper-8-lcm` | 표준 | 사진풍, 일러스트, 회화, 수채화 | 512x512 | 약 4.3GB |
| `sdxs` | 경량, 가장 빠름 | 일반 화풍, 묘사가 단순함 | 512x512 | 약 2.1GB |
| `tiny-sd` | 플랫 | 단색 면 플랫 벡터, 물감 번짐 수채화 | 384x384 | 약 1.1GB |
| `flux2-klein-4b` | 정밀, 가장 느림 | 지시 반영과 인체 형상이 가장 정확 | 384x512 | 약 5.2GB |

- 생성 시간은 실행 환경의 CPU에 따라 달라지므로 첫 장을 생성한 뒤 실측 시간으로 안내한다.
- 표준은 사진 질감, 얕은 피사계 심도, 수채화 번짐에서 묘사가 정밀하다. 플랫 벡터 키워드에서는 형태가 무너진다. 인물 전신에서는 손이 뭉개지거나 발끝이 잘리는 경우가 잦다.
- 경량은 장면 소재를 대체로 지시대로 배치한다. 사진풍 지시에도 일러스트처럼 생성되는 경향이 있고, 같은 인물이 두 번 등장하는 경우가 있다.
- 플랫은 단색 면 채움과 뚜렷한 경계, 물감 번짐과 종이 여백 표현이 다른 프리셋보다 우수하다. 형태 안정성은 낮아 액자 테두리가 함께 그려지거나 인물의 머리가 화면 위로 잘리는 경우가 잦다.
- 정밀은 자연어 문장을 그대로 처리하고 인체 형상이 가장 정확하다. 리눅스 x86_64, Apple Silicon macOS(arm64), 윈도우 x64에서 동작하므로 그 밖의 실행 환경에서는 선택지에서 제외한다. 운영체제는 `PY -c "import platform; print(platform.system(), platform.machine())"`로 확인한다.
- 정밀 프리셋은 생성 전에 디스크 여유 공간이 내려받기 용량보다 큰지 확인한다. 생성 중에는 `--mmap`으로 가중치를 디스크에서 읽으므로 메모리가 작은 환경에서도 동작하지만 속도는 느려진다.

### 모델 고정

- 첫 생성에 사용한 모델은 같은 대화에서 사용자 허락이 있어야 변경한다. 모델을 변경하면 수 GB 내려받기, 장당 시간 변화, 화풍과 인상 변화가 수반된다. 이 변화는 모두 사용자가 예상한 비용과 결과를 벗어난다.
- 후보 선별과 재생성은 선택한 모델 안에서 seed만 바꿔 진행한다.
- 실행이 불가능하면 원인(디스크 부족, 메모리 부족, 내려받기 오류, 운영체제 미지원)을 한 줄로 안내하고 실행 가능한 프리셋을 선택지로 제시한다. 실행 가능한 프리셋이 없으면 이유를 안내하고 작업을 중단한다.

## 생성 전 질의

첫 생성 전에 아래 표에서 해당하는 항목을 한 번에 질의한다. 모델은 결과의 인상과 소요 시간을 결정하고, 후보 배수와 재생성은 확인 시간을 추가하므로 사용자가 선택한다. 구도와 화풍은 질의하지 않고 구도 절과 화풍 절에 따라 정한다.

| 항목 | 질의 조건 | 생략 조건 |
|---|---|---|
| 모델 선택 | 모든 요청 | 사용자가 모델이나 속도, 품질 우선을 직접 언급함 |
| 후보 배수 | 모든 요청 | 사용자가 배수를 직접 언급함 |
| 재생성 상한 | 모든 요청 | 사용자가 횟수나 무제한을 직접 언급함 |
| 크기 | 배너, 표지, 슬라이드 배경처럼 비정사각 규격을 암시하는 사용처인데 크기를 지정하지 않음 | 없음 |
| 치환 확인 | 메시지 요청 | 없음 |
| 도해 동의 | 도해 요청 | 없음 |

- 사용자가 선택지를 직접 지정한 항목만 질의에서 제외한다. 권장 선택지가 있는 항목도 질의한다.
- "알아서 해줘", "기본값으로" 같은 위임 발화에는 기본값 조합을 한 줄로 제시하고 확인을 받는다. 예: "1-a, 2-a, 3-a로 진행할까요?" 기본값은 모델이 표준, 후보 배수가 1배, 재생성 상한이 0회다.
- 후보 배수는 목표 장수에 곱해 한 번에 생성할 장수를 정한다. 배수가 2 이상이면 생성 후 후보 선별 절에 따라 목표 장수만큼 고른다. 자동이면 자동 판단 절에 따라 1-3배 중에서 정한다. 직접 입력은 정수 배수로 받는다.
- 재생성 상한은 목표 이미지 한 장당 다시 생성하는 최대 횟수다. 1회 이상이면 생성 후 재생성 절에 따라 확인하고 필요할 때만 다시 생성한다. 자동이면 자동 판단 절에 따라 0-3회 중에서 정한다. 무제한은 비권장으로 표기하고 선택하면 그대로 따른다.
- 모델 선택지의 표현은 프리셋 표의 역할, 적합한 화풍, 생성 크기, 첫 내려받기를 그대로 옮긴다.
- 같은 대화의 다음 요청은 첫 질의의 답을 그대로 사용한다. 사용자가 선택을 바꾸거나 조건부 항목(크기, 치환 확인, 도해 동의)이 새로 해당하면 해당 항목만 다시 질의한다. 자동으로 답한 항목은 요청마다 다시 판단해 안내한다.

질의 형식은 다음과 같다.

- 해당 항목만 선별해 1번부터 차례로 번호를 붙이고, 선택지는 a), b), c)로 표기한다. 모델 선택이 질의에 포함되면 1번에 둔다. 직접 입력 선택지의 답변 예시는 실제 항목 번호로 맞춘다.
- 사용자가 이미 지정해 질의에서 제외한 항목은 첫 줄 다음에 한 줄로 확인한다. 예: "모델은 경량, 재생성 상한은 2회로 지정하신 대로 진행합니다."
- 화풍을 지정하지 않은 요청은 번호 항목 앞에 추천 화풍과 변경 방법을 한 줄로 안내한다.
- 일반 대화 텍스트의 번호 목록으로 작성하고 코드 블록과 표는 사용하지 않는다.
- 첫 줄에 답변 방법과 답변 예시를 기재한다.
- 각 항목의 기본값에 "(기본값)"을 표기한다.

화풍을 지정하지 않고 사물만 등장하는 지정 피사체 요청의 질의 예시:

> 생성 전에 아래 항목을 확인하겠습니다. 항목 번호와 선택지 기호로 답변해 주세요. (예: 1-a, 2-a, 3-a)
> 화풍은 추천 화풍인 디지털 페인팅으로 진행합니다. 다른 화풍을 원하시면 답변 끝에 적어 주세요. (예: 1-a, 2-a, 3-a, 수채화)
> 1. [모델 선택] 이 대화에서 계속 사용할 모델입니다. 생성 시간은 실행 환경의 CPU에 따라 다르며 첫 장을 생성한 뒤 실측 시간을 안내해 드립니다.
>    a) 표준(DreamShaper 8 LCM)(기본값): 사진풍, 일러스트, 회화, 수채화 전반. 512x512, 첫 내려받기 약 4.3GB
>    b) 경량(SDXS): 가장 빠릅니다. 묘사가 단순하고 사진풍도 일러스트처럼 나옵니다. 512x512, 약 2.1GB
>    c) 플랫(tiny-sd): 단색 면 플랫 벡터와 물감 번짐에 적합합니다. 형태 안정성이 낮습니다. 384x384, 약 1.1GB
>    d) 정밀(FLUX.2 klein 4B): 지시 반영과 인체 형상이 가장 정확하고 가장 느립니다. 384x512, 약 5.2GB
> 2. [후보 배수] 목표 장수보다 많은 후보를 한 번에 생성한 뒤 채택 기준에 맞는 이미지를 골라 전달합니다. 후보 배수가 1배이고 재생성 상한이 0회면 생성 결과를 바로 전달합니다.
>    a) 1배(기본값): 목표 장수만 생성합니다
>    b) 2배
>    c) 3배
>    d) 자동: 인물, 동물, 손이 보이는 구도, 군중처럼 결함이 잦은 요청에서만 배수를 늘립니다. 1-3배 중에서 정한 배수를 생성 전에 안내해 드립니다
>    e) 직접 입력: 정수 배수로 입력해 주세요 (예: 2-e 4)
> 3. [재생성 상한] 전달 전 확인에서 요청과 다르거나 확산모델 특유의 결함이 보이면 같은 프롬프트로 seed만 바꿔 다시 생성합니다. 장당 최대 횟수입니다.
>    a) 0회(기본값): 생성한 결과를 그대로 전달합니다
>    b) 1회
>    c) 3회
>    d) 자동: 피사체의 결함 빈도, 사용처, 모델 속도를 고려해 0-3회 중에서 정합니다. 정한 횟수는 생성 전에 안내해 드립니다
>    e) 직접 입력: 정수 횟수로 입력해 주세요 (예: 3-e 5)
>    f) 무제한(비권장): 채택 기준을 충족할 때까지 계속 생성하며 3회마다 진행 상황을 한 줄로 안내해 드립니다

조건부 항목은 이어서 기재한다. 아래 예시의 번호는 위 3항목에 이어진 경우이며, 앞 항목이 생략되면 1번부터 다시 붙인다. 예:

> 4. [크기] 슬라이드 표지는 보통 16:9 비율입니다. 생성 크기는 512x512이며 더 크게 만들면 확대로 흐림이 생길 수 있습니다.
>    a) 생성 크기 그대로(기본값): 512x512로 전달합니다
>    b) 1920x1080(16:9): 비율에 맞게 잘라낸 뒤 확대합니다
>    c) 직접 입력: 가로x세로로 적어 주세요 (예: 4-c 1600x900)
> 5. [치환 확인] "성장"은 확산모델이 바로 그리지 못하므로 사물로 바꿔 그립니다.
>    a) 새싹이 돋는 화분
>    b) 계단을 오르는 사람의 뒷모습
>    c) 직접 입력: 그릴 사물이나 장면을 적어 주세요

- 정밀 프리셋이 동작하지 않는 실행 환경에서는 정밀 선택지를 제외하고 남은 선택지에 a)부터 차례로 기호를 다시 붙인다.
- 정밀 프리셋이 제외되었으면 질의 첫 줄에 "정밀 모델은 이 운영체제에서 실행할 수 없어 선택지에서 제외했습니다"를 덧붙인다.

### 자동 판단

후보 배수나 재생성 상한의 답이 자동이면 답을 받은 뒤 첫 생성 전에 값을 정한다. 이후 절차의 후보 배수와 재생성 상한은 정한 값을 가리킨다. 두 항목이 모두 자동이면 후보 배수를 먼저 정한다. 재생성 1회가 후보 배수만큼의 새 묶음이기 때문이다.

아래 근거는 결함 가능성 근거다. 두 항목 모두 이 근거로 값을 높인다.

- 주 피사체가 형태가 무너지기 쉬운 피사체(인물, 동물, 자전거나 안경처럼 부품의 연결이 식별에 결정적인 사물)다.
- 인물의 손이나 전신이 화면에 드러나는 구도다.
- 여러 인물이나 배경 군중이 등장하는 장면이다.

후보 배수는 1배를 기준값으로 정한다.

- 결함 가능성 근거가 하나면 2배를 검토한다. 근거가 여럿이면 3배를 검토한다.
- 정밀 프리셋은 1배로 정한다. 장당 시간이 가장 길고 형태가 가장 정확하기 때문이다.

재생성 상한은 0회를 기준값으로 정한다.

- 결함 가능성 근거가 하나면 1회를 검토한다. 근거가 여럿이거나 표지, 배너, 인쇄물처럼 이미지를 크게 쓰는 사용처 또는 품질 우선 언급이 함께 있으면 3회까지 검토한다.
- 후보 배수를 높였으면 목표 이미지 한 장의 최대 생성 장수(`후보 배수 * (1 + 재생성 상한)`)가 늘어나는 정도를 함께 고려한다.
- 정밀 프리셋은 1회 이하로 정한다. 사용자가 속도 우선을 언급했으면 0회로 정한다.
- 무제한은 끝나는 시점이 정해지지 않으므로 자동으로 정하지 않는다.

두 항목에 공통으로 아래 기준을 적용한다.

- 사용자가 작업 시간 한도를 언급했으면 한도를 넘지 않는 값으로 정한다.
- 정한 값과 근거 한 줄을 생성 시작 전에 안내한다. 안내 후 확인을 받지 않고 진행한다. 예: "후보 배수는 2배, 재생성 상한은 1회로 정했습니다. 손이 드러나는 인물 전신 구도라 결함이 잦습니다."

## 소요 시간 안내

첫 장이 끝나면 generate.py 출력의 `seconds`로 남은 장수의 예상 시간을 안내한다.

- 첫 실행에는 모델 내려받기와 적재 시간이 추가된다. 내려받기 용량은 프리셋 표에 기재되어 있다.
- 안내 예: "첫 장은 38초 걸렸습니다. 남은 2장은 약 1분 20초 예상입니다."
- 한 번의 호출로 모든 장을 생성한 경우에는 전달 시 모델 적재 시간(stderr의 `loaded in` 줄)과 장당 실측 시간(stdout JSON의 `seconds`)을 기재한다.
- 정밀 프리셋은 한 장에 수 분에서 수십 분이 걸릴 수 있으므로 생성을 백그라운드로 실행하고 로그로 진행 상황을 확인한다. 에이전트 실행 환경이 대화 턴 사이에 초기화될 수 있으면 실행과 대기를 같은 턴 안에서 완료한다.

## 프롬프트

- 프롬프트는 영어로 작성한다. 한국어 프롬프트는 명사 위주로만 해석되어 화풍과 장소 지시가 거의 반영되지 않는다.
- 피사체와 화풍 키워드를 앞에 배치한다. 수식어를 나열해 길이를 늘리지 않는다.
- 화풍은 기법 이름으로 기재한다. `watercolor illustration`, `flat vector illustration`, `digital painting`, `photorealistic`처럼 기법을 명시한 키워드가 `minimal editorial style` 같은 추상적인 표현보다 잘 반영된다.
- 색은 `muted blue and beige palette`처럼 계열을 직접 명시한다.
- 고유명사, 전문용어, 널리 쓰이지 않는 단어는 모델이 인식하지 못할 수 있다. 확산모델은 학습 이미지 설명에 자주 등장한 단어만 형태와 연결하기 때문이다. 정확한 모습이 요청의 핵심이 아니면 비슷한 흔한 사물로 대체하고, 고유한 모습이 핵심이면 모양, 재질, 색 2-3개로 풀어 서술한다. 예: 잘 알려지지 않은 자동차 모델명은 `a small white electric car`로 대체하고, 게임 속 갑옷 이름은 `golden plate armor`로 풀어 서술한다.
- 이미지 안에 글자를 포함하라는 지시는 작성하지 않는다.
- 작은따옴표(')는 명령행 인용 부호와 충돌하므로 사용하지 않는다.
- 표준, 경량, 플랫 프리셋은 SD 1.5 계열이다. 짧은 키워드형 영문이 잘 반영되고 긴 자연어 문장은 반영이 약하다. 텍스트 해석 범위가 77토큰이므로 초과한 문구는 오류 없이 무시된다. generate.py가 `WARNING: prompt has`로 시작하는 경고와 함께 무시된 문구를 출력하면 프롬프트를 줄여 다시 실행한다.
- 정밀 프리셋은 자연어 문장을 그대로 처리하며 77토큰 제한이 없다. 부정 프롬프트는 사용하지 않는다.
- 재현이 필요하면 seed를 고정하고, 다양한 결과가 필요하면 seed를 변경한다.

## 생성

```
# 도상형, 표준 프리셋
PY scripts/generate.py --prompt "a brass compass on a desk, watercolor illustration, plain background" --out ./outputs --name compass

# 장면형 배너 1024x576, 가로로 긴 규격이므로 피사체를 작게 두고 기준점 0.4로 수평선이 중간보다 약간 아래에 오게 함
PY scripts/generate.py --prompt "a small lighthouse on a rocky coast at sunrise, wide shot, muted blue palette, watercolor illustration" --out ./outputs --name banner --width 1024 --height 576 --anchor-y 0.4

# 세로형 표지 600x800, 세로로 선 피사체의 윗부분을 유지함
PY scripts/generate.py --prompt "an adult man in a gray coat standing in a snowy street, digital painting" --out ./outputs --name cover --width 600 --height 800 --anchor-y 0.0

# 같은 프롬프트 3장(목표 1장, 후보 배수 3배), 모델을 한 번만 적재하고 seed를 1씩 증가시킴
PY scripts/generate.py --preset sdxs --prompt "a stone staircase, digital painting, soft light, plain background" --out ./outputs --name stairs --count 3

# 정밀 프리셋, 백그라운드 실행
setsid nohup PY scripts/generate.py --preset flux2-klein-4b --prompt "an adult woman in a black coat standing on a city street at night, photorealistic" --out ./outputs --name street > ./outputs/street.log 2>&1 < /dev/null &
```

- 생성은 프리셋의 고정 크기로 진행한다. 다른 크기로 생성하면 피사체가 긴 쪽으로 늘어나거나 눌린다.
- `--width`와 `--height`를 함께 지정하면 생성 결과를 그 비율로 잘라낸 뒤 그 크기로 조정한다. 확대는 화소 수만 늘리고 세부 묘사를 추가하지 않으므로, 생성 크기보다 큰 크기로 전달할 때는 흐림이 생길 수 있음을 전달 시 함께 안내한다.
- `--anchor-x`, `--anchor-y`는 잘라낼 기준점이며 0.0은 왼쪽과 위, 0.5는 가운데, 1.0은 오른쪽과 아래다. 기준점은 목표 비율에 따라 정한다. 세로로 길거나 정사각형에 가까운 규격에서는 사람, 탑, 등대처럼 세로로 선 피사체의 윗부분을 `--anchor-y 0.0`으로 유지한다. 가로가 세로의 2배 이상인 규격에서는 높이의 절반 이상이 잘려 나가므로 세로로 선 피사체 전체를 담을 수 없다. 이 경우 프롬프트에 `wide shot`, `in the distance`처럼 피사체를 작게 배치하는 표현을 넣고 `--anchor-y 0.4`에서 시작한다. 모델은 수평선을 화면 가운데 부근에 두는 경우가 많아 이 값에서 수평선이 잘라낸 화면의 중간보다 약간 아래에 온다. 실제 수평선 위치는 생성 전에 알 수 없으므로 열어 보는 설정에서는 결과를 보고 조정한다.
- 잘라낸 결과는 후보 선별이나 재생성을 켠 경우에만 열어 본다. 피사체가 잘렸으면 같은 seed로 기준점만 바꿔 `--overwrite`로 같은 파일에 다시 실행한다. 모델 출력은 같고 잘라내는 위치만 달라지므로 재생성 횟수와 별도로 센다.
- 크기를 지정하지 않으면 프리셋의 생성 크기 그대로 저장한다.
- 여러 장은 `--count`로 생성한다. 스크립트를 반복 호출하면 호출마다 모델 적재 시간이 추가된다. 목표 이미지마다 프롬프트가 다르면 프롬프트마다 한 번씩 실행하고 `--count`에는 후보 배수를 지정한다.
- 같은 경로에 파일이 있으면 번호를 붙여 저장한다. 덮어써야 할 때만 `--overwrite`를 사용한다.
- stdout에는 장마다 경로, 프롬프트, seed, 프리셋, 크기, 소요 초가 JSON 한 줄로 출력된다. 진행 메시지와 경고는 stderr에 출력된다. 대응이 필요한 경고는 `WARNING: prompt has`로 시작하는 77토큰 초과 경고다.
- 종료 코드 7(기계 점검 실패)이 출력되면 seed를 1 올려 다시 실행한다. 결과 이미지가 없는 상태이므로 재생성 횟수와 별도로 센다.
- 정밀 프리셋의 백그라운드 실행은 로그의 진행 표시(`1/4`부터 `4/4`)와 마지막 줄의 JSON으로 완료를 확인한다. 다른 생성 프로세스와 동시에 실행하지 않는다. 동시에 실행하면 메모리 부족으로 종료될 수 있다.

## 채택 기준

후보 선별과 재생성은 아래 기준으로 이미지를 비교한다. 두 절차 중 하나라도 켜진 경우에만 이미지를 열어 본다. 기준은 위에서부터 우선순위다. 모든 항목을 충족한 이미지가 없으면 위쪽 항목을 더 많이 충족한 이미지를 고른다.

1. 지정한 피사체나 장면 소재를 화면에서 바로 알아볼 수 있다.
2. 요청한 화풍과 색 계열이 반영되었다.
3. 확산모델의 전형적인 결함(손가락과 팔다리의 개수 이상, 눈코입의 뭉개짐이나 누락, 끊기거나 뒤엉킨 구조, 같은 피사체의 중복, 의도하지 않은 글자 모양 등)이 보이지 않는다.
4. 요청하지 않은 인물이나 사물이 화면 가운데를 차지하지 않는다.

- 판정이 모호한 항목은 미충족으로 간주한다.
- 비교 결과는 이미지마다 한 줄로 기록한다. 예: `stairs_02: 1 충족, 2 충족, 3 미충족(계단 난간이 중간에서 끊김), 4 충족`

## 후보 선별

후보 배수가 2 이상이면 생성한 후보 전체를 채택 기준으로 비교해 목표 장수만큼 채택한다.

- 채택본은 전달 절에 따라 전달한다. 여분은 생성한 폴더에 그대로 두고 경로와 seed를 함께 안내한다.
- 채택 사유는 채택 기준 번호로 한 줄 기재한다. 예: "stairs_01을 채택했습니다. 후보 중 유일하게 기준 1-4를 모두 충족합니다. stairs_02는 난간이 끊겼고 stairs_03은 계단이 두 개로 겹쳤습니다."
- 모든 후보가 기준 1(피사체 식별)을 충족하지 못하고 재생성 상한이 0회면 그중 가장 나은 후보를 전달하고 미충족 내용을 함께 안내한다.

## 재생성

재생성 상한이 1회 이상이면 전달 전에 채택 기준으로 확인한다. 목표 이미지가 채택 기준을 모두 충족하면 재생성하지 않는다. 충족하지 못하면 같은 프롬프트와 같은 프리셋으로 seed만 바꿔 다시 생성한다.

- 1회 재생성은 후보 배수만큼의 새 묶음 1회다. 배수가 1이면 1장, 3이면 3장을 새로 생성한다.
- 새 seed는 마지막으로 사용한 seed 다음 값부터 쓴다. 이미 본 결과가 다시 나오지 않도록 하기 위해서다.
- 사용자가 요청 내용을 바꾸면 새 요청으로 처리한다. 재생성 횟수를 처음부터 센다.
- 재생성마다 생성 시점까지의 모든 결과를 함께 비교해 가장 나은 결과를 유지한다. 재생성 결과가 이전보다 나쁘면 이전 결과를 유지한다.
- 상한에 도달해도 기준을 모두 충족하지 못하면 가장 나은 결과를 전달하고 미충족 항목을 한 줄로 안내한다. 추가 재생성 여부는 사용자가 정한다.
- 무제한이면 기준을 모두 충족할 때까지 계속 생성한다. 3회마다 진행 상황(시도 횟수, 누적 시간, 남은 미충족 항목)을 한 줄로 안내하며 이어서 진행한다. 사용자가 중단을 요청하면 그 시점의 가장 나은 결과를 전달한다.

## 전달

- 파일 이름은 내용을 알 수 있도록 영문 소문자와 밑줄로 작성한다. 예: `lighthouse_watercolor.png`
- 실행 환경에 파일 제시 수단이 있으면 해당 수단으로 전달하고, 없으면 절대 경로를 안내한다.
- 재현 정보로 프롬프트, seed, 프리셋, 크기를 함께 기록한다.
- 프롬프트에서 모델이 인식하지 못할 단어를 대체하거나 풀어 서술한 경우 원래 단어와 변경한 표현을 함께 안내한다.
- 메시지 요청을 치환해 그린 경우 치환한 사물을 함께 안내한다.
- 크기를 지정받아 잘라낸 경우 잘라낸 방향과 기준점을 함께 안내한다.
- 후보 배수나 재생성을 사용한 경우 채택 사유, 여분 경로, 재생성 횟수를 함께 안내한다.
- 후보 배수나 재생성 상한을 자동으로 정한 경우 재현 정보에 정한 값과 근거를 함께 기록한다.
- JPEG가 필요하면 `--format jpg`로 생성하거나 PNG를 변환한다.
- 바로 전달한 결과에는 "모델 결과를 확인 없이 그대로 전달했습니다"를 한 줄 덧붙인다.

## 자원과 캐시

- 디스크 여유 공간은 내려받기 직전에 확인한다. 프리셋 표의 내려받기 용량보다 작으면 안내하고 더 작은 프리셋을 선택지로 제시한다.
- 생성 프로세스는 하나씩 실행한다. 두 프로세스를 동시에 실행하면 메모리 부족으로 종료될 수 있다.
- 메모리 부족으로 종료되면 남은 프로세스를 정리하고 한 번 다시 시도한다. 재시도 후에도 부족하면 실행 가능한 더 가벼운 프리셋을 선택지로 제시한다.
- 스킬은 캐시 폴더 안의 파일만 삭제한다. 캐시 폴더 밖의 파일과 다른 프로그램의 모델 캐시는 변경하지 않는다.
- 모델은 캐시 폴더 안의 전용 Hugging Face 캐시(`hf`)에 내려받는다. 다른 프리셋의 모델을 삭제하려면 `hf/hub` 아래의 `models--<소유자>--<이름>` 폴더를 삭제한다. 삭제 전에 사용자 확인을 받는다.
- 스킬을 더 사용하지 않는 경우 캐시 폴더 전체를 삭제하면 스킬이 설치한 파일이 모두 제거된다. 삭제는 사용자 확인을 받은 뒤 수행한다.
- 세션 종료 시 파일이 삭제되는 실행 환경에서는 다음 세션에서 가상환경과 모델을 다시 준비한다.
