# 프리셋, 정밀도, 소요 시간, 정밀 프리셋, 캐시

SKILL.md의 프리셋 절과 환경 점검 절을 상세히 기술한 문서다. 프리셋을 선택하거나, 소요 시간을 계산하거나, 정밀 프리셋을 실행하거나, 캐시를 정리할 때 읽는다.

## 프리셋 설정

스텝 수, guidance, 스케줄러는 스크립트에 고정되어 있다. 값을 변경하면 형태가 뭉개지는 조합이 많으므로 기본값을 유지한다.

| 프리셋 | 모델 저장소 | 스케줄러 | 스텝 | guidance | 생성 크기 | 근거 |
|---|---|---|---|---|---|---|
| `dreamshaper-8-lcm` | Lykon/dreamshaper-8-lcm | LCM | 3 | 1.5 | 512x512 | CPU 시간을 줄인 조정값 |
| `sdxs` | IDKiro/sdxs-512-dreamshaper | 모델 기본 | 1 | 0 | 512x512 | 모델 카드 지정값 |
| `tiny-sd` | segmind/tiny-sd | DPM-Solver | 16 | 7.5 | 384x384 | 형태 안정성을 확인한 조정값 |

- `dreamshaper-8-lcm`의 모델 카드 예시는 15스텝과 guidance 2다. LCM은 적은 스텝에서 수렴하도록 증류된 방식이므로 3스텝에서도 형태가 표현된다. 이 스킬은 CPU 시간을 줄이기 위해 3스텝을 사용한다.
- `sdxs`는 `dreamshaper-8-lcm`을 교사 모델로 한 1스텝 증류 모델이다. 모델 카드가 1스텝과 guidance 0을 요구한다.
- `tiny-sd`는 LCM 스케줄러를 사용하면 형태가 뭉개진다. DPM-Solver에서 안정적이다.
- guidance가 1보다 크면 스텝마다 모델을 두 번 계산하므로 시간이 늘어난다.

### 프리셋별 성향

- 표준(`dreamshaper-8-lcm`): 사진 질감, 얕은 피사계 심도, 수채화 번짐에서 묘사가 정밀하다. 화풍 키워드에 따라 사진풍, 일러스트, 수채화를 모두 표현한다. `minimal editorial style` 같은 추상적인 화풍 지시에서는 인물 사진 구도로 치우치는 경우가 있고, `watercolor illustration`처럼 기법 이름을 사용하면 장면 구도로 복귀한다. 플랫 벡터 키워드에서는 형태가 뭉개진 뒤 피사체가 무너진다. 인물 전신에서는 옷의 좌우가 어긋나거나 손이 뭉개지는 경우가 잦고, 정사각형 전신 구도에서 발끝이 화면 밖으로 잘리는 경우가 흔하다.
- 경량(`sdxs`): 가장 빠르며 장면 소재를 대체로 지시대로 배치한다. 묘사는 표준보다 단순하다. 사진풍 지시에도 디지털 페인팅처럼 생성되는 경향이 있다. 플랫 요청은 음영이 남은 준플랫으로 생성된다. 같은 인물이 두 번 등장하거나 요청하지 않은 소품이 함께 그려지는 경우가 있다.
- 플랫(`tiny-sd`): 단색 면 채움과 뚜렷한 경계의 플랫 벡터, 물감 번짐과 종이 여백 표현에서 다른 프리셋보다 우수하다. 형태 안정성은 경량보다 낮아 피사체가 배경과 분리되어 보이기도 한다. 잘린 사각 액자가 함께 그려지는 경우가 있고, 인물 구도에서는 머리가 화면 위로 잘리는 경우가 잦다. 형태 안정성이 필요한 수채화는 표준에 `watercolor illustration`을 사용한다.
- 플랫에서 피사체가 누락되면 seed를 한 번 변경해 시도하고, 그래도 누락되면 경량에 `flat vector art, solid flat colors, no shading`을 추가하는 대안을 사용자에게 제시한다. 프리셋은 허락을 받은 경우에만 변경한다.
- 플랫의 가중치는 PyTorch pickle 형식(.bin)으로 배포된다. diffusers와 transformers는 이 파일을 텐서만 읽는 방식(weights only)으로 적재한다.

## 정밀도 선택

생성과 부위 다시 그리기는 float32 또는 bfloat16으로 모델을 적재한다. 스크립트가 아래 순서로 자동으로 선택한다.

1. CPU가 bfloat16 명령을 직접 지원하면(x86의 AVX512_BF16 또는 AMX) bfloat16을 사용한다. 속도가 빠르고 메모리 사용량도 적다.
2. 지원하지 않고 전체 메모리가 프리셋의 float32 기준 이상이면 float32를 사용한다.
3. 두 조건에 모두 해당하지 않으면 bfloat16을 사용한다. 메모리에는 적재되지만 명령을 에뮬레이션해 계산하므로 여러 배 느리다. 이 경우 사용자에게 속도 저하를 안내한다.

bfloat16 연산을 하드웨어로 처리하는 명령은 AVX512_BF16과 AMX에 있다. 이런 명령이 없는 CPU에서는 bfloat16 행렬 곱을 다른 명령으로 분해해 계산하므로 float32보다 느려진다. `probe.py`의 `cpu.native_bf16`이 이 판단 값이다. `--dtype fp32` 또는 `--dtype bf16`으로 직접 지정할 수도 있다.

| 대상 | float32 기준(전체 메모리) | bfloat16 기준(전체 메모리) |
|---|---|---|
| `dreamshaper-8-lcm` | 6.0GB | 3.5GB |
| `sdxs` | 3.5GB | 2.5GB |
| `tiny-sd` | 4.0GB | 3.0GB |
| 부위 다시 그리기 | 6.0GB | 3.5GB |

기준은 float32 가중치 파일 크기에 생성 중 작업 메모리를 더한 값이다. 전체 메모리가 bfloat16 기준보다 적으면 generate.py가 종료 코드 6으로 중단된다.

## 소요 시간 예상

`probe.py --estimate`는 아래 두 값으로 장당 예상 초를 산출한다.

- 벤치마크: 1024x1024 행렬 곱을 약 1.5초 동안 반복해 float32와 bfloat16의 초당 연산량(GFLOPS)을 측정한다. 모든 논리 코어를 사용한다.
- 작업량: 프리셋이 한 장을 생성하는 데 필요한 실효 연산량(GFLOP)이다. 기준 CPU에서 "장당 실제 초 x 같은 CPU의 벤치마크 GFLOPS"로 산출해 probe.py의 `WORK_GFLOP_PER_IMAGE`에 기록했다.
- 예상 초 = 작업량 / 실행 환경의 벤치마크 GFLOPS. 정밀도는 generate.py가 선택할 정밀도와 같은 값을 사용한다.

생성 연산의 대부분이 행렬 곱이므로 이 비례 관계가 대체로 성립하지만 메모리 속도, 캐시 크기, 다른 프로그램의 부하, 발열에 따라 오차가 발생한다. 따라서 안내할 때 항상 예상치임을 명시하고, 첫 장 생성이 끝나면 실제 초로 다시 안내한다.

- 첫 실행은 모델 적재와 내려받기 시간이 추가된다. 적재에는 보통 수 초에서 수십 초가 소요된다.
- 작업량을 다시 보정하려면 같은 실행 환경에서 `probe.py --estimate`의 GFLOPS와 한 장의 실제 `seconds`를 곱해 해당 값을 갱신한다.

## 정밀 프리셋 (FLUX.2 klein 4B)

40억 파라미터 모델을 stable-diffusion.cpp의 사전 빌드 실행 파일과 4비트 양자화 파일로 실행한다. 컴파일은 필요하지 않다. 지시 반영과 인체 형상이 SD 1.5 계열보다 정확하지만 가장 느리다.

- 실행 파일: stable-diffusion.cpp 릴리스 하나를 고정해 사용하고 SHA-256으로 확인한다. 리눅스 x86_64용만 고정되어 있으므로 다른 운영체제에서는 선택지에서 제외한다.
- 모델 파일: 확산 모델(FLUX.2 klein 4B의 GGUF Q4_0), 텍스트 인코더(Qwen3 4B의 GGUF Q4_K_M), VAE(FLUX.2 klein 4B 공식 저장소의 VAE) 세 개를 각 공식 배포처에서 고정 리비전으로 내려받는다. 합계 약 5.2GB다.
- 설정: 4스텝, cfg 1.0(업스트림 문서의 예시값), 메모리 매핑(`--mmap`), VAE 타일 디코딩을 고정했다. 메모리 매핑을 비활성화하면 가중치가 메모리로 복사되어 메모리가 작은 환경에서 종료된다.
- 크기: 기본 384x512, 최대 512x704 화소다. 스텝 시간이 화소 수에 비례해 늘어나므로 큰 규격은 화질 보정으로 맞춘다.
- 프롬프트: 자연어 문장을 그대로 처리한다. 77토큰 제한이 없고 부정 프롬프트는 사용하지 않는다.
- 결과가 한 가지 색으로 채워져 있으면 종료 코드 7로 중단된다. 양자화 방식이 다른 파일은 오류 없이 흰 이미지를 출력하는 경우가 있으므로 고정한 파일 외에는 사용하지 않는다.
- 한 번에 한 장만 생성한다. 실행 전에 `probe.py --estimate`의 예상 시간을 안내한다.

실행 시간이 길어 백그라운드로 실행하고 로그로 진행 상황을 확인한다. 에이전트 실행 환경이 대화 턴 사이에 초기화될 수 있으면, 실행과 대기를 같은 턴 안에서 완료한다.

```
setsid nohup PY scripts/generate_klein.py "an adult woman in a black coat standing on a city street at night, photorealistic, framed from head to thighs" ./outputs/klein.png --seed 42 > ./outputs/klein.log 2>&1 < /dev/null &
```

- 로그의 진행 표시(`1/4`부터 `4/4`)와 결과 파일 생성, 마지막 줄의 JSON을 확인한다.
- 다른 생성 프로세스와 동시에 실행하지 않는다. 동시에 실행하면 메모리 부족으로 종료된다.

## 캐시

스킬이 내려받는 파일은 모두 캐시 폴더(`~/.cache/image-gen`, `IMAGE_GEN_HOME`으로 변경 가능) 아래에 저장된다. 모델은 캐시 폴더 안의 전용 Hugging Face 캐시(`hf`)에 내려받는다. 사용자의 다른 도구가 사용하는 Hugging Face 캐시와 분리되어 있으므로 삭제해도 다른 도구에 영향이 없다. 다른 곳에 같은 모델이 있어도 한 번 새로 내려받는다.

| cache.py 대상 | 삭제 범위 |
|---|---|
| `dreamshaper-8-lcm`, `sdxs`, `tiny-sd` | 해당 모델 저장소 |
| `flux2-klein-4b` | 정밀 프리셋의 모델 세 저장소와 실행 파일 폴더(`klein`) |
| `inpaint` | 부위 다시 그리기 모델과 LCM-LoRA |
| `face` | 얼굴 복원 가중치 폴더(`face`) |
| `sr` | 화질 보정 가중치 폴더(`sr`) |
| `all` | 가상환경(`venv`)을 제외한 캐시 폴더 전체 |

- Hugging Face 캐시는 실제 파일을 공용 저장 폴더에 보관하고 모델 폴더에는 링크만 생성한다. 모델 폴더만 삭제하면 디스크 공간이 회수되지 않으므로 cache.py로 삭제한다.
- 기본 프리셋의 캐시는 같은 대화에서 계속 사용하므로 유지한다. 디스크가 다음 내려받기에 부족하면 기본 프리셋 이외의 캐시부터 삭제한다.
- 삭제한 모델을 다시 사용하면 다시 내려받는다. 연속 생성이 끝난 뒤에 삭제한다.
- 스킬을 더 사용하지 않는 경우 `cache.py delete all` 실행 후 가상환경 폴더(`venv`)를 삭제하면 스킬이 설치한 파일이 모두 제거된다. 가상환경 폴더는 사용자 확인을 받은 뒤 삭제한다.
