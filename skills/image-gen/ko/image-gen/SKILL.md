# 로컬 모델을 활용한 이미지 생성

이 스킬은 로컬 모델을 활용해 이미지를 생성한다. 모델 파일은 스킬을 실행하는 환경(실행 환경)에 내려받는다. 생성은 실행 환경의 CPU로 한다. 네트워크는 패키지와 모델 파일을 내려받을 때만 쓴다. 프롬프트는 외부 이미지 생성 서비스로 보내지 않는다. 결과는 PNG 또는 JPEG 파일이다.

확산모델은 글자, 정확한 연결선, 수치, 정확한 개수를 그리지 못한다. 이런 요소가 필요한 요청은 전하려는 뜻을 사물이나 장면으로 바꿔 그린다. 글자는 완성된 이미지 위에 편집 도구로 얹는다.

## 작업 순서

1. 환경 준비: 스킬 전용 가상환경을 만들고 의존성을 설치한다.
2. 환경 점검: probe.py로 실행 가능 여부와 예상 소요 시간을 확인한다.
3. 요청 분류와 구도: 무엇을 어떤 구도로 그릴지 정한다.
4. 프리셋: 모델을 고른다.
5. 생성 전 질의: 보정 방침을 한 번에 묻고 preflight.json에 기록한다.
6. 프롬프트: 영문 프롬프트를 쓴다.
7. 생성: generate.py 또는 generate_klein.py를 실행한다.
8. 점검과 결함 대응: 산출물을 열어 보고 결함을 고친다.
9. 화질 보정: 고른 경우 채택본에 한 번 적용한다.
10. 전달: 파일과 재현 정보를 전달한다.

## 명령 표기

- `PY`는 스킬 전용 가상환경의 파이썬이다. 리눅스와 macOS는 `~/.cache/image-gen/venv/bin/python`, 윈도우는 `%USERPROFILE%\.cache\image-gen\venv\Scripts\python.exe`다.
- `scripts/`는 이 스킬 폴더 안의 scripts 폴더 경로로 바꿔 쓴다.
- 명령은 사용자의 작업 폴더에서 실행한다. 결과 파일은 사용자가 정한 경로에 저장한다. 정한 경로가 없으면 실행 환경이 정한 산출 폴더에 저장하고, 산출 폴더도 없으면 작업 폴더에 저장한 뒤 절대 경로를 알린다.
- 스크립트는 리눅스, macOS, 윈도우에서 같은 명령으로 동작한다. 정밀 프리셋만 리눅스 x86_64에서 동작한다.
- 스킬이 내려받는 모든 파일은 캐시 폴더 `~/.cache/image-gen`에 모인다. 환경변수 `IMAGE_GEN_HOME`으로 위치를 바꿀 수 있다.
- GitHub에서 파일을 받는 기능은 정밀 프리셋 엔진(`leejet/stable-diffusion.cpp`), 화질 보정(`xinntao/Real-ESRGAN`), 얼굴 복원(`TencentARC/GFPGAN`, `xinntao/facexlib`)이다. 세션에 GitHub 저장소를 연결하는 도구가 실행 환경에 있으면 각 기능의 첫 실행 전에 해당 저장소로 호출한다. 소유자와 저장소 이름은 `/` 앞뒤를 각각 따로 전달한다. 도구 응답이 안내하는 접근 경로를 따른다. 도구가 없거나 호출이 거부되면 이 단계를 건너뛴다.

## 환경 준비

패키지는 스킬 전용 가상환경 하나에만 설치한다. 사용자 환경에 이미 있는 패키지는 지우거나 바꾸지 않는다. GPU용 torch나 CUDA 패키지가 깔린 환경이어도 그대로 둔다. 전용 환경에 CPU용 torch를 따로 설치하므로 둘은 서로 영향을 주지 않는다.

```
python3 -m venv ~/.cache/image-gen/venv
PY -m pip install --no-cache-dir torch torchvision --index-url https://download.pytorch.org/whl/cpu
PY -m pip install --no-cache-dir diffusers transformers accelerate safetensors peft huggingface_hub pillow numpy
```

- `python3`가 없으면 `python`으로 실행한다. 윈도우는 `%USERPROFILE%\.cache\image-gen\venv` 경로로 만든다.
- torchvision은 torch와 같은 CPU 인덱스에서 함께 설치한다. torch만 설치하면 후처리 패키지가 CUDA용 torchvision을 끌어와 `operator torchvision::nms does not exist` 오류가 난다.
- `--no-cache-dir`은 내려받은 설치 파일을 공용 pip 캐시에 남기지 않는다. 설치가 끝난 뒤 따로 지울 캐시가 생기지 않는다.
- 가상환경을 만들 수 없으면(venv 모듈 누락 등) 현재 파이썬 환경에 설치해도 되는지 사용자에게 묻는다. 허락을 받은 경우에만 그 환경에 설치하고, externally-managed-environment 오류가 나면 `--break-system-packages`를 붙인다.
- pip 설치 권한이 없으면 생성할 수 없다. 이유를 알리고 멈춘다.
- 파이썬을 실행할 수 없는 환경도 생성할 수 없다. 이유를 알리고, 영문 프롬프트와 프리셋 설정을 전달해 사용자가 파이썬을 쓸 수 있는 환경에서 생성하도록 안내한다.
- 후처리 의존성은 후처리를 쓰기로 한 경우에만 references/postprocess.md의 설치 절을 따라 설치한다.

## 환경 점검

```
PY scripts/probe.py --estimate
```

probe.py는 JSON 하나를 출력한다. 아래 값으로 다음 행동을 정한다.

| 값 | 뜻 | 조치 |
|---|---|---|
| `hub_reachable` | 모델 저장소에 닿는지 | false이고 캐시에도 모델이 없으면 이유를 알리고 멈춘다 |
| `dependencies` | 패키지 설치 여부 | torch, diffusers, transformers 중 false가 있으면 환경 준비로 돌아간다 |
| `free_disk_gb` | 캐시 폴더의 디스크 여유 | 프리셋 표의 내려받기 용량과 비교한다 |
| `memory.total_gb` | 전체 메모리 | 모자라면 generate.py가 실행 전에 종료 코드 6으로 멈춘다 |
| `cpu.native_bf16` | CPU의 bfloat16 명령 지원 | 생성 정밀도 선택에 쓰인다(references/models.md) |
| `precise_tier_supported` | 정밀 프리셋 실행 가능 여부 | false면 정밀 프리셋을 선택지에서 뺀다 |
| `estimate.seconds_per_image` | 프리셋별 장당 예상 초 | 소요 시간 안내에 쓴다 |

### 소요 시간 안내

소요 시간은 실행 환경의 CPU를 잰 값으로 계산해 알린다. `--estimate`는 CPU의 행렬 곱 속도를 몇 초 동안 재고, 그 속도로 프리셋별 작업량을 나눠 장당 예상 초를 낸다. 메모리 속도, 동시에 도는 다른 프로그램, 발열 때문에 실제 시간과 차이가 나므로 안내할 때마다 예상치라고 밝힌다.

- 안내 예: "실행 환경 기준 예상 장당 약 40초, 3장 약 2분입니다. 예상치이며 첫 장을 만든 뒤 다시 알려드립니다."
- 첫 실행에는 모델 내려받기 시간이 더해진다. 내려받기 용량은 프리셋 절의 표에 있다.
- 첫 장이 끝나면 generate.py 출력의 `seconds`로 남은 장의 예상을 다시 알린다.
- 계산 방법과 작업량 값은 references/models.md의 소요 시간 예상 절에 있다.

## 요청 분류

생성 전에 요청을 아래 셋 중 하나로 나눈다. 기준은 사용자가 그릴 대상을 구체적으로 정했는지다.

| 유형 | 판정 | 처리 |
|---|---|---|
| 지정 피사체 | 사물, 인물, 동물, 장소처럼 윤곽이 보이는 대상을 사용자가 정함 | 정한 대상을 그대로 그린다 |
| 메시지 요청 | 추상 개념이나 전하려는 메시지만 줌 | 그릴 수 있는 사물이나 장면으로 한 번 바꿔 그린다 |
| 도해 요청 | 글자 라벨, 연결선, 정확한 개수, 수치가 필요함(흐름도, 개념도, 구조도, 차트, 지표 그림) | 한계와 대체안을 알리고 동의를 받은 뒤 그린다 |

- 상징성이 있는 사물을 사용자가 정했다면 이미 고른 결과이므로 바꾸지 않는다.
- 사물과 메시지를 함께 주면 사물을 그리고, 메시지는 화풍과 색으로 반영한다.
- 치환 규칙, 치환 예시표, 동의 질의 문안은 references/composition.md에 있다.

## 구도

구도는 도상형과 장면형 둘이다. 사용자가 구도를 말하면 따르고, 말하지 않으면 쓰일 자리로 정한다. 쓰일 자리도 없으면 도상형으로 만든다.

| 구도 | 모습 | 주 용도 | 프롬프트 순서 |
|---|---|---|---|
| 도상형 | 피사체를 화면 가운데에 두고 단색 배경을 씀 | 본문 삽화, 장표 삽화, 사물 하나를 내세운 그림 | 피사체, 화풍, 색, `plain background` |
| 장면형 | 보편적인 소재 2-3개에 시간대 1개와 색 계열 1개를 더함 | 배경 이미지, 배너, 표지, 간지, 슬라이드 배경, 풍경 그림 | 소재 조합, 시간대, 색, 화풍 |

- 도상형은 피사체가 화면에서 바로 알아보이는 결과를 채택한다.
- 장면형은 개별 사물보다 장면 전체의 분위기를 채택 기준으로 삼는다.
- 장면형의 소재 고르는 법과 시간대, 색 지정은 references/composition.md의 장면 구성 절을 따른다.

## 프리셋

프리셋은 모델과 고정 설정의 묶음이다. 화풍은 프롬프트로 바꾸고, 모델은 프리셋으로 바꾼다.

| 프리셋 | 역할 | 잘 맞는 화풍 | 생성 크기 | 첫 내려받기 |
|---|---|---|---|---|
| `dreamshaper-8-lcm` | 표준, 기본값 | 사진풍, 일러스트, 회화, 수채화 | 512x512 | 약 4.3GB |
| `sdxs` | 경량, 가장 빠름 | 일반 화풍, 묘사가 단순함 | 512x512 | 약 2.1GB |
| `tiny-sd` | 플랫 | 단색 면 플랫 벡터, 물감 번짐 수채화 | 384x384 | 약 1.1GB |
| `flux2-klein-4b` | 정밀, 가장 느림 | 지시 반영과 인체 형상이 가장 정확 | 384x512 | 약 5.2GB |

- 화풍과 품질 요구가 모두 없으면 표준을 쓴다.
- 표준은 플랫 벡터 키워드에서 형태가 무너진다. 플랫 벡터 요청에는 플랫이나 경량을 쓴다.
- 플랫은 인물이 주 피사체인 구도에서 머리가 잘리거나 액자 테두리가 끼는 일이 잦다. 인물이 주 피사체면 표준이나 정밀을 쓴다.
- 경량은 사진풍 지시에도 일러스트처럼 나오는 경향이 있다.

### 모델 선택 질의

아래 조건 중 하나라도 맞으면 생성 전 질의에 모델 선택을 넣는다. 조건에 맞지 않으면 묻지 않고 표준으로 진행한다. 사용자가 모델, 속도 우선, 품질 우선을 직접 말했다면 묻지 않고 그대로 따른다.

| 조건 | 선택지 |
|---|---|
| 한 번에 10장 이상 요청 | 표준, 경량 |
| 인물이 주 피사체(전신, 손이 보이는 구도 포함) | 표준, 정밀 |
| 플랫 벡터 또는 물감 번짐 질감 요청 | 플랫, 경량 |
| 환경 점검에서 자원이 모자람 | 실행 가능한 프리셋만 |

- 선택지마다 장당 예상 시간(예상치 표기), 첫 내려받기 용량, 화질과 화풍의 차이를 함께 적는다.
- 초안, 시안, 반복 확인은 이미지 생성의 흔한 형태라서 모델 선택 질의나 경량 선택의 이유가 되지 않는다.
- 10장 기준은 표준으로 전체 시간이 길어져 경량과의 차이가 체감되는 물량이다. 1-9장은 차이가 작다.

### 모델 고정

- 첫 생성에 쓴 모델은 같은 대화에서 사용자 허락이 있어야 바꾼다. 모델을 바꾸면 수 GB 내려받기, 장당 시간 증가, 화풍과 인상 변화가 따라오고, 모두 사용자가 예상한 비용과 결과를 벗어난다.
- 결함 대응은 고른 모델 안에서 seed 변경, 가장자리 트림, 프롬프트 우회, 후처리, 구도 우회로 한다. 모델 교체는 자동 수단에 넣지 않는다.
- 모델 교체가 도움이 된다고 판단되면 재생성 상한에 닿았을 때 선택지 하나로 제시한다. 내려받기 용량, 장당 예상 시간, 달라지는 점을 함께 적는다. 사용자가 고르면 preflight.py를 `--preset`만 바꿔 다시 실행한 뒤 교체한다.
- 실행이 불가능하면 원인(디스크 부족, 메모리 부족으로 인한 종료, 내려받기 오류)을 한 줄로 알리고 실행 가능한 프리셋을 선택지로 준다. 디스크 부족이 기본 프리셋 이외의 캐시를 지워 풀리면 묻지 않고 다시 시도한다. 실행 가능한 프리셋이 없으면 이유를 알리고 멈춘다.

## 생성 전 질의

첫 생성 전에 아래 표에서 해당하는 항목을 한 번에 묻는다. 후처리 설치 용량, 인상 변화, 질감 손실은 사람마다 받아들이는 정도가 달라 사용자가 고른다. 결함이 생긴 뒤에 물으면 자동 진행을 원하는 사용자의 작업이 끊기므로 질의는 생성 전에 한다.

| 항목 | 묻는 조건 | 생략 조건 |
|---|---|---|
| 화질 보정 | 모든 요청 | 없음 |
| 가장자리 트림 | 모든 요청 | 없음 |
| 결함 후처리 | 인물 또는 정밀 사물이 나옴 | 없음 |
| 얼굴 복원 범위 | 인물이 나옴 | 없음 |
| 손가락 다시 그리기 | 인물이 나옴 | 결함 후처리가 우회만 자동 |
| 후보 생성 | 모든 요청 | 없음 |
| 후보 선택 | 표시 경로가 있음 | 후보 생성이 1배 |
| 여분 후보 보정 | 모든 요청 | 후보 생성이 1배, 또는 화질 보정이 안 함이면서 얼굴 복원 범위가 상시 이외 |
| 모델 선택 | 모델 선택 질의 조건에 맞음 | 사용자가 모델이나 속도, 품질 우선을 직접 말함 |

- 인물이 한 명이라도 화면에 나오면 크기, 비중, 화풍과 상관없이 인물이 나오는 요청이다. 멀리 작게 나오는 인물일수록 얼굴 결함이 심하므로 비중이 작다는 이유로 생략하지 않는다. 애매하면 인물이 나오는 요청으로 본다.
- 정밀 사물은 자전거, 안경, 의자, 사다리, 건반처럼 부품이 이어진 방식이 알아보는 데 결정적인 사물이다.
- 사용자가 선택지를 직접 말한 항목만 뺀다. 권장 선택지가 있는 항목도 묻는다.
- "알아서 해줘", "기본값으로" 같은 위임에는 권장 조합을 한 줄로 보여 주고 확인을 받는다. 예: "1-b, 2-b, 3-a, 4-a, 5-a, 6-a로 진행할까요?" 비사진 화풍의 권장 조합은 얼굴 복원 미사용이다. 예: "1-b, 2-b, 3-a, 4-c, 5-a, 6-a로 진행할까요?" 권장 조합의 후보 생성은 1배다.
- 사물만 나오는 요청도 화질 보정, 가장자리 트림, 후보 생성은 묻는다.
- 질의 전에 전달 절의 표시 경로 판정을 한다. 표시 경로가 없으면 그 절의 표대로 항목과 선택지를 줄인다.
- 후보 생성은 목표 장수보다 많은 후보를 한 번에 만들어 고르는 방식이다. 결함 대응 1단계(같은 프롬프트로 seed만 바꿔 다시 생성)를 생성 시점에 미리 하는 셈이다. 기본값 1배는 목표 장수만 만든다.
- 후보 생성의 고정 배수 선택지에는 총 장수(목표 장수와 배수의 곱)와 probe.py 기준 예상 시간을 적고 예상치라고 밝힌다. 자동 선택지에는 1배부터 자동 판단의 상한까지 총 장수 범위와 예상 시간 범위를 적는다.
- 직접 입력은 정수 배수로 받는다. 목표 이미지마다 프롬프트가 다르면 총 장수만으로는 프롬프트별 장수가 정해지지 않기 때문이다.
- 여분 후보 보정의 선택지 문구에는 이 질의에서 고를 수 있는 일괄 처리 이름만 적는다. 사물만 나오는 요청은 화질 보정만 적는다.
- 모델 선택 질의의 10장 조건은 목표 장수로 판정한다. 배수는 같은 질의에서 받으므로 모델 질의 여부를 배수 답에 맞출 수 없다.
- 자동이 1배로 정해지면 후보 선택과 여분 후보 보정의 답은 쓰지 않는다.

질의 형식은 이렇다.

- 해당 항목만 골라 1번부터 차례로 번호를 붙이고, 선택지는 a), b), c)로 적는다. 모델 선택은 항상 마지막 번호다.
- 조건부 항목(손가락 다시 그리기, 후보 선택, 여분 후보 보정)은 설명 첫 문장에 해당 조건을 실제 항목 번호로 적는다.
- 일반 대화 텍스트의 번호 목록으로 쓰고 코드 블록과 표는 쓰지 않는다.
- 첫 줄에 답하는 방법과 답 예시를 적는다.
- 사진풍이나 수채화 요청이면 화질 보정 항목에 경고 한 줄을 붙인다. 예: "사진풍과 수채화는 보정하면 피부 결과 종이 질감이 지워집니다."
- 플랫 벡터, 선화, 셀 채색 같은 비사진 화풍이면 얼굴 복원 범위의 미사용을 권장으로 표시하고 이유 한 줄을 붙인다. 예: "이 화풍은 복원한 얼굴만 사진처럼 바뀌어 그림체와 어긋납니다." 얼굴 복원 도구는 실제 사진 얼굴로 학습되었기 때문이다.

인물이 나오는 요청의 질의 예시:

> 생성 전에 아래 항목을 확인합니다. 항목별 번호와 선택지로 답해 주세요. (예: 1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c)
> 1. [화질 보정] 결함 대응과 트림을 마친 뒤 마지막에 한 번 적용합니다.
>    a) 안 함: 트림이나 목표 크기 확대에서 흐림이 생깁니다
>    b) general: 화풍 전반에 무난합니다
>    c) flat: 플랫 벡터 전용입니다
> 2. [가장자리 트림] 손가락 같은 결함이 화면 가장자리에 걸리면 다시 생성하기 전에 그 가장자리를 조금 잘라냅니다. 잘린 결함은 화면에서 완전히 사라지므로 이 경우 가장 확실한 방법입니다.
>    a) 미사용: 재생성과 우회로만 대응합니다
>    b) 동일 비율만: 화면 비율을 유지한 채 필요한 만큼 잘라 원래 크기로 되돌립니다. 확인 없이 적용하고 전달할 때 알려드립니다
>    c) 자유 비율까지: b로 안 되는 경우 비율을 바꾼 후보(예: 가로로 긴 구도)를 미리보기로 보여드리고 고르신 비율로 적용합니다
>    d) 자유 비율까지 자동: b로 안 되는 경우 원래 구도에 가장 가까운 후보를 제가 골라 적용하고 알려드립니다. 화면 비율이 바뀔 수 있습니다
> 3. [결함 후처리] 인물의 얼굴, 옷, 착용물에 형태 결함이 생길 수 있습니다.
>    a) 후처리 자동: seed 변경과 프롬프트 우회로 남은 결함을 얼굴 복원과 부위 다시 그리기로 자동 보정합니다 (설치 약 1.2GB, 부위 다시 그리기를 쓰면 약 2.3GB 추가)
>    b) 우회만 자동: 설치 없이 seed 변경, 프롬프트 우회, 구도 우회로 진행합니다
>    c) 결함마다 질의: 후처리가 필요할 때마다 여쭙니다
> 4. [얼굴 복원 범위]
>    a) 결함 시에만: 얼굴 결함이 보일 때 3번 방침대로 적용합니다
>    b) 상시: 결함과 상관없이 인물 이미지 전부에 얼굴 복원을 적용합니다. 눈동자와 치아가 선명해집니다 (3번이 b여도 적용, 설치 약 1.2GB)
>    c) 미사용: 얼굴 복원을 설치하지도 쓰지도 않습니다. 얼굴 결함은 seed 변경과 우회로 대응하고, 3번의 옷과 착용물 다시 그리기는 그대로 둡니다
> 5. [손가락 다시 그리기] 3번이 a나 c일 때만 해당합니다. 손가락 결함에는 효과가 낮아 seed 변경, 가장자리 트림, 프롬프트 우회를 항상 먼저 시도합니다.
>    a) 미사용(권장): 남은 결함은 손이 화면 밖에 놓이는 구도로 대응합니다
>    b) 사용: 남은 결함에 한 번 시도하고 전후를 비교해 보여드립니다. 따로 드러난 손에만 쓰며 손 크기와 자세가 달라질 수 있습니다
> 6. [후보 생성] 목표 장수보다 많은 후보를 한 번에 만들어 고릅니다. 결함이 생긴 뒤 다시 생성을 기다리는 일이 줄어듭니다. 장수와 시간은 목표 1장 기준이며 실행 환경 기준 예상치입니다.
>    a) 1배: 1장, 약 40초
>    b) 2배: 2장, 약 1분 20초
>    c) 3배: 3장, 약 2분
>    d) 자동: 1-3장, 약 40초-2분. 인물, 손, 군중처럼 결함이 잦은 요청만 늘리고 정한 배수를 생성 전에 알려드립니다
>    e) 직접 입력: 정수 배수로 적어 주세요 (예: 6-e 4)
> 7. [후보 선택] 6번이 a가 아닐 때만 해당합니다.
>    a) 에이전트 선택: 결함이 없는 후보부터 차례로 목표 장수만큼 제가 골라 끝까지 진행합니다
>    b) 사용자 선택: 생성 직후 번호를 붙인 모아보기 한 장을 보여드리고, 번호로 고르신 후보로 마무리합니다
> 8. [여분 후보 보정] 6번이 a가 아니고, 1번이 a가 아니거나 4번이 b일 때만 해당합니다. 고르지 않은 후보(여분)에 화질 보정과 얼굴 상시 복원을 할지 정합니다. 결함 수리는 채택본에만 합니다.
>    a) 채택본만: 여분은 생성 원본 그대로 드립니다. 원하시는 여분은 나중에 따로 마무리할 수 있습니다
>    b) 전 후보: 여분도 보정한 상태로 드립니다. 후처리 시간이 후보 수만큼 늘어납니다
>    c) 자동: 작업에 맞춰 a와 b 중 하나를 제가 정하고 생성 전에 알려드립니다

모델 선택 조건에 맞으면 마지막 번호로 이어서 적는다. 예:

> 9. [모델 선택] 인물이 주 피사체라 모델에 따라 형태 결함 빈도가 달라집니다. 시간은 실행 환경 기준 예상치입니다.
>    a) 표준(DreamShaper 8 LCM): 장당 약 40초, 512px, 손과 옷 결함이 잦습니다
>    b) 정밀(FLUX.2 klein 4B): 장당 약 15분, 384x512, 형태가 가장 정확합니다. 첫 실행에 약 5.2GB를 내려받습니다

예시의 시간은 형식을 보이기 위한 값이다. 실제 질의에는 probe.py의 예상치를 쓴다.

### 후보 배수 자동 판단

후보 생성의 답이 자동이면 답을 받은 뒤 preflight.py로 기록하기 전에 배수를 정한다. 기준값은 1배다. 아래 근거가 있을 때만 배수를 올린다.

- 주 피사체가 형태가 무너지기 쉬운 피사체(인물, 동물, 정밀 사물)다.
- 인물의 손이나 전신이 화면에 드러나는 구도다.
- 여러 인물이나 배경 군중이 나오는 장면이다.

아래 경우는 1배를 유지한다.

- 정밀 프리셋을 쓴다. 장당 시간이 가장 길고 형태 정확도가 가장 높다.
- 형태가 무너지기 쉬운 피사체가 없는 사물 도상이나 풍경 장면이다.

배수는 아래 한도 안에서 정한다.

- 근거가 하나면 2배를 검토한다. 근거가 겹치면 3배까지 검토한다.
- 상한은 3배다.
- 총 장수(목표 장수와 배수의 곱)는 10장 미만으로 둔다. 모델 선택 질의는 목표 장수로 판정해 생략되므로, 자동 배수가 총 시간을 모델 선택 기준 이상으로 늘리지 않게 한다. 목표 4장이면 2배, 5장 이상이면 1배가 상한이다.
- 정한 배수, 근거 한 줄, 총 장수, 예상 시간을 생성 시작 전에 알린다. 알린 뒤 확인을 받지 않고 진행한다. 트림의 자유 비율까지 자동과 같은 방식이다.

### 여분 후보 보정 자동 판단

여분 후보 보정의 답이 자동이면 배수가 정해진 뒤 preflight.py로 기록하기 전에 정한다. 기준값은 a) 채택본만이다. 채택본만은 생성 원본이 남아 나중에 여분을 따로 마무리할 수 있으므로 되돌릴 수 있는 선택이다. 전 후보는 후처리 시간을 미리 쓰므로 되돌릴 수 없는 선택이다.

아래 경우에만 b) 전 후보로 정한다.

- 후보 선택이 사용자 선택이고 얼굴 복원 범위가 상시다. 복원 전후의 얼굴 차이가 커서, 모아보기를 복원본으로 만들어야 사용자가 최종 모습으로 고를 수 있다.
- 요청에 여러 안을 모두 받겠다는 뜻이 드러나 있다.

- 화질 보정만 해당하는 경우는 a를 유지한다. 화질 보정은 주로 선명도와 크기를 바꾸므로 구도와 표정 비교에 영향이 적다.
- 정한 선택과 근거 한 줄을 생성 시작 전에 알린다. 알린 뒤 확인을 받지 않고 진행한다.

### 답변 기록

답을 받으면 preflight.py로 출력 폴더에 preflight.json을 쓴다. 생성 스크립트는 이 파일이 없으면 종료 코드 2로 멈추고, preflight.py는 필요한 답이 빠지면 빠진 항목을 나열하고 종료 코드 2로 멈춘다. 질문 없이 임의로 채운 값은 기록하지 않는다.

```
# 인물이 나옴, 답 "1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c", 자동 판단으로 3배와 전 후보를 정함
PY scripts/preflight.py --out ./outputs --subject person --display available --enhance general --trim free --postfix auto --face-scope always --finger-inpaint off --candidates auto --candidates-resolved 3 --candidates-reason "전신과 손이 드러나는 인물 구도" --candidate-pick user --spare-finish auto --spare-finish-resolved all --spare-finish-reason "사용자 선택과 얼굴 상시 복원" --user-reply "1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c"

# 사물만 나옴, 모델 선택 포함, 답 "1-b, 2-b, 3-a, 6-b"
PY scripts/preflight.py --out ./outputs --subject other --display available --enhance general --trim same --candidates 1 --preset sdxs --user-reply "1-b, 2-b, 3-a, 6-b"
```

- `--subject`는 인물이 나오면 `person`, 인물 없이 정밀 사물이 나오면 `precise-object`, 그 외는 `other`다.
- `--display`는 전달 절의 표시 경로 판정 결과다. 표시 경로가 있으면 `available`, 없으면 `none`이다. `none`에서 `--trim free`, `--finger-inpaint on`, `--candidate-pick user`는 종료 코드 2로 거부된다.
- `--candidates`는 정수 배수나 `auto`다. `auto`면 정한 배수(1-3)를 `--candidates-resolved`에, 근거 한 줄을 `--candidates-reason`에 적는다.
- `--candidate-pick`은 에이전트 선택이 `auto`, 사용자 선택이 `user`다.
- `--spare-finish`는 채택본만이 `adopted`, 전 후보가 `all`, 자동이 `auto`다. `auto`면 정한 값을 `--spare-finish-resolved`에, 근거 한 줄을 `--spare-finish-reason`에 적는다.
- 후보 선택과 여분 후보 보정은 정해진 배수가 2 이상일 때만 필요하다. 쓰지 않는 항목은 null로 기록된다. 이후 단계는 `candidates_resolved`와 `spare_finish_resolved`에 기록된 값을 쓴다.
- `--user-reply`에는 사용자 답을 그대로 적는다.
- 같은 대화의 다음 생성은 같은 출력 폴더의 기록을 그대로 쓴다. 사용자가 선택을 바꾸거나 인물 등장 여부가 달라지면 preflight.py를 다시 실행한다.
- 화풍이 바뀌어 사진풍이나 수채화가 새로 되면 화질 보정 항목만 다시 묻는다. 사진풍과 비사진 화풍 사이를 오가면 얼굴 복원 범위 항목만 다시 묻는다.

## 프롬프트

- 프롬프트는 영어로 쓴다. 한국어 프롬프트는 명사 위주로만 읽혀 화풍과 장소 지시가 거의 반영되지 않는다.
- 피사체와 화풍 키워드를 앞에 둔다. 수식어를 늘어놓아 길이를 늘리지 않는다.
- 화풍은 기법 이름으로 적는다. `watercolor illustration`, `flat vector illustration`, `digital painting`, `photorealistic`처럼 기법을 밝힌 키워드가 `minimal editorial style` 같은 추상적인 표현보다 잘 반영된다.
- 색은 `muted blue and beige palette`처럼 계열을 직접 적는다.
- 이미지 안에 글자를 넣으라고 쓰지 않는다.
- 작은따옴표(')는 명령행 인용과 부딪히므로 쓰지 않는다.
- 표준, 경량, 플랫 프리셋은 SD 1.5 계열이다. 짧은 키워드형 영문에 반응하고 긴 자연어 문장은 반영이 약하다. 문장 해석 창이 77토큰이라 그 뒤의 글은 오류 없이 무시된다. 시작과 끝 표지를 뺀 75토큰은 영어로 약 50단어다. generate.py가 무시된 문구를 경고로 출력하면 프롬프트를 줄여 다시 실행한다.
- 정밀 프리셋은 자연어 문장을 그대로 받고 77토큰 제한이 없다. 부정 프롬프트는 쓰지 않는다.
- 재현하려면 seed를 고정하고, 다양하게 만들려면 seed를 바꾼다.
- 결함을 피하려는 우회 지시(모자, 선글라스, 장갑 등)는 첫 생성 프롬프트에 넣지 않는다. 결함을 확인한 뒤에 쓴다. 사용자가 처음부터 요청한 착용물은 원래 의도이므로 넣는다.

## 생성

```
# 도상형, 기본 프리셋
PY scripts/generate.py --prompt "a brass compass on a desk, watercolor illustration, plain background" --out ./outputs --name compass

# 장면형 배너 1024x576, 세로로 선 피사체의 윗부분을 남김
PY scripts/generate.py --prompt "a lighthouse on a rocky coast at sunrise, muted blue palette, watercolor illustration" --out ./outputs --name banner --width 1024 --height 576 --anchor-y 0.0

# 같은 프롬프트 4장, 모델을 한 번만 적재하고 seed를 1씩 늘림
PY scripts/generate.py --prompt "a stone staircase, digital painting, soft light, plain background" --out ./outputs --count 4

# 플랫 프리셋
PY scripts/generate.py --preset tiny-sd --prompt "flat vector illustration of a single lighthouse, muted blue palette, plain background" --out ./outputs --name lighthouse_flat
```

- 생성은 항상 정사각형으로 한다. 직사각형으로 생성하면 피사체가 긴 쪽으로 늘어나거나 눌린다. 다른 비율은 생성 뒤 잘라서 만든다.
- `--width`와 `--height`는 함께 쓴다. `--anchor-x`, `--anchor-y`는 잘라낼 기준점이며 0.0은 왼쪽과 위, 0.5는 가운데, 1.0은 오른쪽과 아래다. 사람, 탑, 등대처럼 세로로 선 피사체는 `--anchor-y 0.0`으로 윗부분을 남긴다. 하늘과 수평선 장면은 지평선이 아래 3분의 1에 오도록 기준점을 정한다.
- 화질 보정을 고른 경우 결과는 목표 비율만 맞춘 작업 크기로 저장된다(512px 생성의 1024x576 목표는 512x288). 목표 크기는 마무리의 finalize.py가 만든다.
- 화질 보정을 안 하기로 한 경우 결과를 이 단계에서 목표 크기로 늘린다. 늘리기는 화소 수만 늘리고 세부 묘사를 더하지 않는다. 384px 플랫 프리셋 결과는 512px로 늘려 저장한다.
- 여러 장은 `--count`로 만든다. 스크립트를 반복 호출하면 호출마다 모델 적재 시간이 더해진다.
- 같은 경로에 파일이 있으면 번호를 붙여 저장한다. 덮어써야 할 때만 `--overwrite`를 쓴다.
- stdout에는 장마다 경로, 프롬프트, seed, 프리셋, 정밀도, 크기, 걸린 초가 JSON으로 나온다.
- 비율을 바꿔 잘라낸 결과는 열어서 피사체가 잘리지 않았는지 확인한다. 잘렸으면 같은 seed로 기준점만 바꿔 다시 실행한다. 기준점으로도 피사체가 다 담기지 않으면 목표 비율에 맞는 구도(멀리 배치, 상반신 등)를 프롬프트에 넣어 다시 생성한다.
- 정밀 프리셋은 references/models.md의 정밀 프리셋 절을 따라 generate_klein.py로 실행한다.

정해진 배수가 2 이상이면 목표 장수와 배수의 곱만큼 후보를 만든다. 이 후보 묶음을 후보 풀이라 한다.

```
# 같은 프롬프트로 목표 2장, 후보 2배
PY scripts/generate.py --prompt "a red bicycle leaning against a brick wall, side view, watercolor illustration" --out ./outputs --name bicycle --count 4

# 정밀 프리셋, 후보 2배, seed와 파일 이름을 바꿔 한 장씩
PY scripts/generate_klein.py "an elderly man reading a newspaper on a park bench, photorealistic" ./outputs/reader-01.png --seed 42
PY scripts/generate_klein.py "an elderly man reading a newspaper on a park bench, photorealistic" ./outputs/reader-02.png --seed 43
```

- 프롬프트가 같은 목표 이미지는 `--count`에 목표 장수와 배수의 곱을 주어 한 번에 실행한다. 목표 이미지마다 프롬프트가 다르면 프롬프트마다 `--count`에 배수를 준다.
- 정밀 프리셋은 한 번에 한 장만 만든다. 후보는 seed를 1씩 늘리고 파일 이름을 바꿔 장마다 따로 실행한다. 앞 실행이 끝난 뒤 다음을 실행한다.
- 후보는 출력 폴더에 만든다. 생성 스크립트와 finalize.py는 출력 폴더의 preflight.json을 읽으므로, 하위 폴더에 저장하면 종료 코드 2로 멈춘다. 여분은 채택 뒤에 `candidates` 폴더로 옮긴다(점검 절의 후보 채택).

## 점검

generate.py는 저장 직후 파일 크기(10KB 초과), 매직 바이트(JPEG `FFD8FF`, PNG `89504E47`), 픽셀 크기를 스스로 확인한다. 종료 코드 7이 나오면 눈으로 보기 전에 다시 생성한다.

기계 점검을 통과하면 파일을 직접 열어 본다.

- 사용자가 정한 피사체가 그대로 나왔는가
- 프롬프트의 화풍과 색이 반영되었는가
- 쓰일 크기로 줄였을 때 형태를 알아볼 수 있는가
- 요청하지 않은 인물이 화면 가운데를 차지하지 않았는가
- 사물이 의도보다 많거나 같은 피사체가 두 번 나오지 않았는가
- 인물과 동물의 이목구비, 팔다리 수, 손발 모양이 맞는가
- 옷과 착용물에 끊긴 안경테, 사라진 끈, 요청하지 않은 성기나 여성 유두 노출이 없는가
- 발견한 결함이 화면의 네 변 중 하나에 닿거나 가까운가
- 도해 요청을 바꿔 그린 경우 그림이 원래 메시지를 전하는가
- 피사체가 가로나 세로로 눌려 있으면 정사각형으로 다시 생성한다

화질 보정을 고른 경우 위 점검은 작업 크기 결과로 한다.

### 후보 채택

정해진 배수가 2 이상이면 후보 풀 전체를 점검한 뒤 목표 장수만큼 채택한다.

1. 모든 후보를 원본 파일로 위 항목대로 점검한다. 얼굴 복원 범위가 상시면 여분 후보 보정의 정해진 값을 따른다. 전 후보면 모든 후보에 얼굴 복원을 한 번씩 적용한 뒤 복원본으로 점검한다. 채택본만이면 원본으로 점검하고, 채택 뒤 채택본에만 복원한 다음 복원본으로 판정한다.
2. 모든 후보로 모아보기를 만든다. 모든 후보에 얼굴 복원을 적용했으면 복원본으로 만들고, 그 밖에는 생성 원본으로 만든다. 화질 보정은 채택 뒤에 적용하므로 모아보기에 반영하지 않는다.
3. 후보 선택의 답대로 채택한다.
4. 여분 후보 보정이 전 후보이고 화질 보정을 고른 경우 여분마다 화질 보정을 한 번 적용한다. 입력은 복원본이 있으면 복원본, 없으면 생성 원본이다. finalize.py는 출력 폴더의 preflight.json을 읽으므로 옮기기 전에 출력 폴더에서 적용한다.
5. 여분의 생성 원본과 보정본을 출력 폴더 안의 `candidates` 폴더로 옮긴다. 채택본은 출력 폴더에 남겨 결함 대응, 트림, 화질 보정으로 마무리한다.

```
PY scripts/contact_sheet.py ./outputs/bicycle-01.png ./outputs/bicycle-02.png ./outputs/bicycle-03.png ./outputs/bicycle-04.png --out ./outputs/bicycle_sheet.png
PY scripts/contact_sheet.py "./outputs/reader-0?_face.png" --out ./outputs/reader_sheet.png   # 복원본, 와일드카드는 스크립트가 펼친다
```

- 모아보기는 입력 순서대로 1번부터 번호를 붙인다. stdout에는 번호와 파일의 대응이 JSON으로 나온다.
- 모아보기는 구도와 표정을 고르는 용도다. 작은 결함은 원본 후보 파일로 판정한다.
- 에이전트 선택은 아래 채택 순서로 목표 장수만큼 채택하고 끝까지 진행한다. 채택한 후보, 순위, 근거를 기록한다.
- 사용자 선택은 생성 직후 모아보기를 보여 주고 번호로 고르게 한다. 후보마다 찾은 결함을 한 줄씩 함께 알린다. 고른 후보로 결함 대응과 마무리를 한다.
- 사용자가 고른 후보에 해결 수단이 없는 결함이 있으면, 그 결함을 알리고 남은 후보에서 다시 고를지 결함 대응 2단계로 갈지 묻는다.
- 표시 경로가 없으면 사용자 선택을 묻지 않고 에이전트 선택으로 진행한다.

에이전트 채택 순서는 이렇다.

1. 결함이 없는 후보
2. 트림으로 풀리는 결함만 있는 후보(트림 답이 미사용 이외). 동일 비율 트림으로 풀리는 후보가 자유 비율 트림 후보보다 앞선다.
3. 후처리로 풀리는 결함만 있는 후보(결함 후처리 답이 후처리 자동이나 결함마다 질의). 얼굴 상시 복원으로 풀리는 얼굴 결함은 결함 후처리 답과 상관없이 이 순위에 든다.

- 같은 순위 안에서는 원 요청의 피사체, 구도, 화풍에 가장 가까운 후보를 고른다.
- 해결 수단이 없는 결함 후보는 채택하지 않는다. 다시 생성해야 풀리는 일반 결함(화풍, 색, 개수 등)도 여기에 든다.
- 목표 장수를 채우지 못한 자리는 결함 대응 절차로 채운다. 형태가 무너지기 쉬운 피사체는 1단계 재생성 없이 2단계부터 진행한다(references/defects.md).

### 후보 모드의 처리 범위

기존 항목의 답은 후보 모드에서 아래처럼 적용한다.

| 기존 항목 | 후보 모드 동작 |
|---|---|
| 화질 보정 | 여분 후보 보정의 정해진 값대로 채택본에만, 또는 모든 후보에 한 번씩 적용한다 |
| 가장자리 트림 | 채택한 후보의 결함에만 적용한다. 미사용이면 채택 순서의 2순위가 없다 |
| 결함 후처리 | 후처리 자동은 채택 순서의 3순위로 쓴다. 우회만 자동은 후처리가 있어야 풀리는 후보를 해결 수단이 없는 후보로 본다. 결함마다 질의는 앞 순위 후보가 모자랄 때만 묻는다 |
| 얼굴 복원 범위 | 상시는 여분 후보 보정의 정해진 값을 따른다. 결함 시에만은 결함 후처리 규칙을 따른다. 미사용은 해당이 없다 |
| 손가락 다시 그리기 | 채택한 후보에만 적용한다 |

- 결함별 수리(트림, 결함 시 얼굴 복원, 강도를 낮춘 얼굴 재복원, 부위 다시 그리기, 손가락 다시 그리기)는 답과 상관없이 채택본에만 적용한다. 결함 수리는 후보마다 판정과 사용자 확인이 필요하므로, 여분까지 적용하면 질의와 시간이 후보 수만큼 늘어난다.
- 얼굴 상시 복원은 후보마다 한 번만 적용한다. 강도를 낮춰 다시 적용하는 일은 결함 수리이므로 채택본에만 한다.
- 사용자가 여분 일부를 원하면 그 후보의 생성 원본을 출력 폴더로 옮겨 채택본과 같은 수리와 마무리 절차를 추가로 실행한다. 화질 보정은 한 번만 적용하므로 생성 원본에서 다시 시작한다.

## 결함 대응

결함을 찾으면 references/defects.md의 순서를 따른다. 흐름은 이렇다.

1. 트림 우선 판정: 결함이 가장자리에 닿고 그 결함 말고는 다시 만들 이유가 없는 경우다. 트림 답변이 동일 비율만, 자유 비율까지, 자유 비율까지 자동 중 하나라면 재생성보다 가장자리 트림을 먼저 한다.
2. 일반 결함: 화풍, 색, 개수, 배경, 구도 문제는 프롬프트 수정과 seed 변경으로 고친다.
3. 형태가 무너지기 쉬운 피사체(인물, 동물, 정밀 사물, 배경 군중): 대응 1단계 seed 변경, 2단계 프롬프트 우회, 3단계 후처리, 4단계 구도 우회 순으로 진행한다.
4. 재생성 상한에 닿으면 가장 나은 결과를 결함 위치와 함께 보여 주고 다음 방향을 묻는다.

정해진 배수가 2 이상이면 후보 풀 교체가 형태 결함 대응 1단계를 대신한다. 후보 풀이 바닥나면 1단계 재생성 없이 2단계로 간다. 일반 결함은 후보 풀 교체 횟수를 seed 변경 횟수에 더한다. 세부 규칙과 재생성 상한은 references/defects.md에 있다.

후처리 도구(얼굴 복원, 부위 다시 그리기, 손가락 다시 그리기)의 선택, 강도, 설치, 정리는 references/postprocess.md에 있다.

## 화질 보정

화질 보정은 4배 초해상도로 키운 뒤 목표 크기로 줄이는 마무리 단계다. 생성 크기가 512px 이하라서 트림, 비정사각 규격, 목표 크기를 맞추려면 확대가 필요하다. 단순 확대는 흐려지므로 확대를 모두 이 단계로 대신한다.

| 선택 | 맞는 대상 | 대가 |
|---|---|---|
| 안 함 | 질감 보존이 우선인 요청 | 원본의 흐림이 남는다 |
| general | 화풍 전반, 인물 포함 | 사진풍과 수채화에서 피부 결과 종이 질감이 지워진다 |
| flat | 플랫 벡터 배경 | 인물에서 밀랍 같은 질감, 콧구멍 경계 과장, 머리카락 뭉침이 생긴다 |

- 결함 대응과 트림을 모두 마친 채택본에 한 번만 적용한다. 생성 직후에 적용하면 트림 뒤 다시 늘리거나 두 번 적용하게 되어 밀랍 같은 질감이 쌓인다. 얼굴 복원과 부위 다시 그리기도 보정 전 크기에서 동작하도록 맞춰져 있다. 버려지는 시도에는 적용하지 않으므로 추가 시간은 채택본 한 장 몫이다.
- 후보 모드에서는 여분 후보 보정의 정해진 값을 따른다. 전 후보면 여분에도 한 장에 한 번씩 적용하므로 추가 시간이 후보 수만큼 늘어난다. 여분은 결함 수리를 하지 않으므로 채택 직후 출력 폴더에서 적용한다.
- 질감 손실은 후처리의 성질이라 프롬프트나 seed로 되돌릴 수 없다.
- 초해상도는 이목구비 결함을 고치지 못한다. 얼굴 결함은 결함 대응 절차로 고친다.
- 첫 사용 때 가중치(수 MB)를 GitHub에서 내려받고 SHA-256으로 확인한다. 추가 설치는 필요 없다.
- 목표 크기는 입력의 4배 이내로 준다. 넘는 부분은 단순 확대가 된다.
- 생성 프로세스가 끝난 뒤 따로 실행하므로 메모리를 겹쳐 쓰지 않는다.

```
PY scripts/finalize.py ./outputs/banner_trim.png ./outputs/banner_final.png --size 1024x576
```

- `--size`를 주지 않으면 768x768로 만든다. 방식은 preflight.json의 답을 따른다.
- 트림에서 비율을 바꾼 경우 edge_trim.py가 출력한 `target=WxH`를 `--size`에 그대로 넣는다. 원래 목표 크기를 넣으면 원래 비율로 다시 잘려 지킨 부위가 잘린다.
- 결과를 열어 밀랍 같은 질감, 콧구멍과 입술 경계 과장, 머리카락 뭉침, 질감 손실을 확인한다. 부작용이 보이면 보정 전 채택본을 같은 크기로 늘린 안과 나란히 보여 주고 사용자에게 고르게 한다.
- 부작용 비교는 채택본에만 한다. 표시 경로가 없으면 부작용이 적은 안을 직접 고르고 전달할 때 이유를 한 줄로 알린다.

## 전달

- 파일 이름은 내용을 알 수 있는 영문 소문자와 밑줄로 짓는다. 예: `lighthouse_flat_vector.png`
- 실행 환경에 파일 제시 수단이 있으면 그 수단으로 전달하고, 없으면 절대 경로를 알린다.
- 재현 정보로 프롬프트, seed, 프리셋, 크기, 화질 보정 선택을 함께 남긴다.
- 후보 모드에서는 채택본과 함께 후보 폴더 경로와 모아보기를 제시한다. 재현 정보에 후보마다의 seed, 정해진 배수, 여분 후보 보정 선택을 더한다. 자동으로 정한 배수와 여분 후보 보정 선택은 근거를 함께 적는다.
- 트림한 결과는 트림 사실, 절단선이 지나는 부위, 잘린 비율(자유 비율이면 채택 비율과 남은 면적)을 함께 알린다.
- JPEG가 필요하면 `--format jpg`로 생성하거나 PNG를 변환한다.

### 표시 경로 판정

사용자에게 이미지를 보여 주는 모든 지점은 이 판정을 따른다. 판정은 생성 전 질의 단계에서 한 번 한다. 에이전트가 가진 도구와 실행 위치를 보고 아래 셋 중 하나로 정한다.

| 표시 경로 | 판정 기준 | `--display` |
|---|---|---|
| 파일 제시 도구 | 실행 환경에 파일을 사용자 화면에 보여 주는 도구가 있음 | `available` |
| 공유 파일 시스템 | 에이전트가 사용자의 컴퓨터에서 실행되어, 절대 경로를 알리면 사용자가 열 수 있음 | `available` |
| 표시 경로 없음 | 제시 도구가 없는 원격 실행 환경처럼, 절대 경로를 알려도 사용자가 열 수 없음 | `none` |

표시 경로가 없으면 지점마다 아래처럼 처리한다.

| 이미지 표시 지점 | 표시 경로가 없을 때 |
|---|---|
| 후보 선택의 사용자 선택 | 항목을 묻지 않고 에이전트 선택으로 진행한다 |
| 가장자리 트림의 자유 비율까지 | 선택지에서 뺀다 |
| 손가락 다시 그리기의 사용 | 선택지에서 뺀다. 전후 비교 확인이 필요하기 때문이다 |
| 비사진 화풍의 얼굴 복원 전후 비교 | 화풍과 어울리는 안을 직접 고르고 전달할 때 이유를 한 줄로 알린다 |
| 화질 보정 부작용 비교 | 부작용이 적은 안을 직접 고르고 전달할 때 이유를 한 줄로 알린다 |
| 재생성 상한 도달 | 결함 위치를 글로 설명하고 다음 방향을 묻는다 |

- 선택지를 뺀 항목은 남은 선택지에 a)부터 차례로 다시 붙인다. 손가락 다시 그리기는 미사용만 남아도 묻고 답을 기록한다.

## 자원과 캐시

- 디스크와 메모리는 내려받기와 실행 직전마다 새로 확인한다. 모델, 얼굴 복원, 부위 다시 그리기, 화질 보정이 각각 가중치를 내려받으므로 같은 대화 안에서도 여유 공간이 계속 바뀐다.
- 생성, 얼굴 복원, 부위 다시 그리기, 화질 보정은 각각 별도 프로세스로 하나씩 실행한다. 앞 프로세스가 끝났는지 확인한 뒤 다음을 실행한다. 두 개를 겹치면 메모리 부족으로 종료될 수 있다.
- 메모리 부족으로 종료되면 남은 프로세스를 정리하고 한 번 다시 시도한다. 그래도 모자라면 실행 가능한 더 가벼운 프리셋을 선택지로 묻는다.
- 스킬은 캐시 폴더 안의 파일만 지운다. 캐시 폴더 밖의 파일과 다른 프로그램의 모델 캐시는 건드리지 않는다.
- 디스크가 모자라면 사용을 마친 후처리 가중치, 기본 프리셋 이외의 프리셋 순서로 지운다. 같은 대화에서 다시 쓸 파일은 다시 내려받는 시간이 들므로 끝까지 둔다.
- 지운 대상과 지운 뒤의 여유 공간을 기록한다.
- 세션이 끝나면 파일이 지워지는 실행 환경에서는 다음 세션에서 가상환경과 모델을 다시 준비한다.

```
PY scripts/cache.py list
PY scripts/cache.py delete sdxs
PY scripts/cache.py delete all    # 가상환경을 뺀 캐시 전체
```
