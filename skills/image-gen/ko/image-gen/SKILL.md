# 로컬 모델을 활용한 이미지 생성

이 스킬은 로컬 모델을 활용해 이미지를 생성한다. 모델 파일은 스킬을 실행하는 환경(실행 환경)에 내려받는다. 생성은 실행 환경의 CPU에서 수행한다. 네트워크는 패키지와 모델 파일을 내려받을 때만 사용한다. 프롬프트는 외부 이미지 생성 서비스로 전송하지 않는다. 결과물은 PNG 또는 JPEG 파일이다.

확산모델은 글자, 정확한 연결선, 수치, 정확한 개수를 표현하지 못한다. 이런 요소가 필요한 요청은 전달하려는 의미를 사물이나 장면으로 치환해 그린다. 글자는 완성된 이미지 위에 편집 도구로 추가한다.

## 작업 순서

1. 환경 준비: 스킬 전용 가상환경을 생성하고 의존성을 설치한다.
2. 환경 점검: probe.py로 실행 가능 여부와 예상 소요 시간을 확인한다.
3. 요청 분류와 구도: 그릴 대상과 구도를 정한다.
4. 프리셋: 모델을 선택한다.
5. 생성 전 질의: 생성과 보정 방침을 한 번에 질의하고 preflight.json에 기록한다. 후보 생성의 답이 1배가 아니면(자동 포함) 기록 전에 references/candidates.md를 읽는다. 첫 프롬프트 우회의 답이 미사용이 아니면 기록 전에 references/defects.md를 읽는다.
6. 프롬프트: 영문 프롬프트를 작성한다.
7. 생성: generate.py 또는 generate_klein.py를 실행한다.
8. 점검과 결함 대응: 점검 전 읽기 절의 참조 문서를 먼저 읽는다. 산출물을 열어 확인하고 결함을 보정한다.
9. 화질 보정: 선택한 경우 채택본에 한 번 적용한다. 전달 전에 4배 결과물로 화질 보정 후 재점검을 진행한다.
10. 전달: 파일과 재현 정보를 전달한다.

## 명령 표기

- `PY`는 스킬 전용 가상환경의 파이썬이다. 리눅스와 macOS는 `~/.cache/image-gen/venv/bin/python`, 윈도우는 `%USERPROFILE%\.cache\image-gen\venv\Scripts\python.exe`다.
- `scripts/`는 이 스킬 폴더 안의 scripts 폴더 경로로 대체해 사용한다.
- 명령은 사용자의 작업 폴더에서 실행한다. 결과 파일은 사용자가 지정한 경로에 저장한다. 지정한 경로가 없으면 실행 환경이 지정한 산출 폴더에 저장하고, 산출 폴더도 없으면 작업 폴더에 저장한 뒤 절대 경로를 안내한다.
- 스크립트는 리눅스, macOS, 윈도우에서 같은 명령으로 동작한다. 정밀 프리셋은 리눅스 x86_64에서만 동작한다.
- 스킬이 내려받는 모든 파일은 캐시 폴더 `~/.cache/image-gen`에 저장된다. 환경변수 `IMAGE_GEN_HOME`으로 위치를 변경할 수 있다.
- GitHub에서 파일을 내려받는 기능은 정밀 프리셋 엔진(`leejet/stable-diffusion.cpp`), 화질 보정(`xinntao/Real-ESRGAN`), 얼굴 복원(`TencentARC/GFPGAN`, `xinntao/facexlib`)이다. 세션에 GitHub 저장소를 연결하는 도구가 실행 환경에 있으면 각 기능의 첫 실행 전에 해당 저장소를 대상으로 호출한다. 소유자와 저장소 이름은 `/` 앞뒤를 각각 별도로 전달한다. 도구 응답이 안내하는 접근 경로를 따른다. 도구가 없거나 호출이 거부되면 이 단계를 생략한다.

## 환경 준비

패키지는 스킬 전용 가상환경 하나에만 설치한다. 사용자 환경에 이미 설치된 패키지는 삭제하거나 변경하지 않는다. GPU용 torch나 CUDA 패키지가 설치된 환경도 그대로 유지한다. 전용 환경에 CPU용 torch를 별도로 설치하므로 두 환경은 서로 영향을 주지 않는다.

```
python3 -m venv ~/.cache/image-gen/venv
PY -m pip install --no-cache-dir torch torchvision --index-url https://download.pytorch.org/whl/cpu
PY -m pip install --no-cache-dir diffusers transformers accelerate safetensors peft huggingface_hub pillow numpy
```

- `python3`가 없으면 `python`으로 실행한다. 윈도우는 `%USERPROFILE%\.cache\image-gen\venv` 경로에 생성한다.
- torchvision은 torch와 같은 CPU 인덱스에서 함께 설치한다. torch만 설치하면 후처리 패키지가 CUDA용 torchvision을 함께 설치해 `operator torchvision::nms does not exist` 오류가 발생한다.
- `--no-cache-dir`은 내려받은 설치 파일을 공용 pip 캐시에 보관하지 않는다. 설치가 끝난 뒤 별도로 삭제할 캐시가 생기지 않는다.
- 가상환경을 생성할 수 없으면(venv 모듈 누락 등) 현재 파이썬 환경에 설치할지 사용자에게 질의한다. 허락을 받은 경우에만 해당 환경에 설치하고, externally-managed-environment 오류가 발생하면 `--break-system-packages`를 추가한다.
- pip 설치 권한이 없으면 생성할 수 없다. 이유를 안내하고 작업을 중단한다.
- 파이썬을 실행할 수 없는 환경도 생성할 수 없다. 이유를 설명하고, 영문 프롬프트와 프리셋 설정을 전달해 사용자가 파이썬을 사용할 수 있는 환경에서 생성하도록 안내한다.
- 후처리 의존성은 후처리를 사용하기로 한 경우에만 references/postprocess.md의 설치 절에 따라 설치한다.

## 환경 점검

```
PY scripts/probe.py --estimate
```

probe.py는 JSON 하나를 출력한다. 아래 값에 따라 다음 조치를 정한다.

| 값 | 의미 | 조치 |
|---|---|---|
| `hub_reachable` | 모델 저장소 접속 가능 여부 | false이고 캐시에도 모델이 없으면 이유를 안내하고 작업을 중단한다 |
| `dependencies` | 패키지 설치 여부 | torch, diffusers, transformers 중 false가 있으면 환경 준비 단계로 돌아간다 |
| `free_disk_gb` | 캐시 폴더의 디스크 여유 공간 | 프리셋 표의 내려받기 용량과 비교한다 |
| `memory.total_gb` | 전체 메모리 | 부족하면 generate.py가 실행 전에 종료 코드 6으로 중단된다 |
| `cpu.native_bf16` | CPU의 bfloat16 명령 지원 | 생성 정밀도 선택에 사용된다(references/models.md) |
| `precise_tier_supported` | 정밀 프리셋 실행 가능 여부 | false면 정밀 프리셋을 선택지에서 제외한다 |
| `estimate.seconds_per_image` | 프리셋별 장당 예상 초 | 소요 시간 안내에 사용한다 |

### 소요 시간 안내

소요 시간은 실행 환경의 CPU 측정값으로 계산해 안내한다. `--estimate`는 CPU의 행렬 곱 속도를 수 초 동안 측정하고, 프리셋별 작업량을 그 속도로 나눠 장당 예상 초를 산출한다. 메모리 속도, 동시에 실행 중인 다른 프로그램, 발열로 인해 실제 시간과 차이가 발생하므로 안내할 때마다 예상치임을 명시한다.

- 안내 예: "실행 환경 기준 예상 소요 시간은 장당 약 40초, 3장 약 2분입니다. 예상치이므로 첫 장을 생성한 뒤 다시 안내해 드리겠습니다."
- 첫 실행에는 모델 내려받기 시간이 추가된다. 내려받기 용량은 프리셋 절의 표에 기재되어 있다.
- 첫 장 생성이 끝나면 generate.py 출력의 `seconds`로 남은 장의 예상 시간을 다시 안내한다.
- 계산 방법과 작업량 값은 references/models.md의 소요 시간 예상 절에 수록되어 있다.

## 요청 분류

생성 전에 요청을 아래 세 유형 중 하나로 분류한다. 분류 기준은 사용자가 그릴 대상을 구체적으로 지정했는지 여부다.

| 유형 | 판정 | 처리 |
|---|---|---|
| 지정 피사체 | 사물, 인물, 동물, 장소처럼 윤곽이 드러나는 대상을 사용자가 지정함 | 지정한 대상을 그대로 그린다 |
| 메시지 요청 | 추상 개념이나 전달하려는 메시지만 제시함 | 그릴 수 있는 사물이나 장면으로 한 번 치환해 그린다 |
| 도해 요청 | 글자 라벨, 연결선, 정확한 개수, 수치가 필요함(흐름도, 개념도, 구조도, 차트, 지표 그림) | 한계와 대체안을 안내하고 동의를 받은 뒤 그린다 |

- 사용자가 상징성이 있는 사물을 지정했다면 이미 선택을 마친 결과이므로 변경하지 않는다.
- 첫 프롬프트 우회가 최대 우회면 지정 피사체도 같은 의미를 전달하는 다른 사물이나 장면으로 교체할 수 있다. 교체하기 전에 교체한 구성을 제시하고 확인을 받는다.
- 사물과 메시지를 함께 제시하면 사물을 그리고, 메시지는 화풍과 색으로 반영한다.
- 치환 규칙, 치환 예시표, 동의 질의 문안은 references/composition.md에 수록되어 있다.

## 미성년자 보호

미성년자의 노출과 성적 묘사(성행위 포함)는 생성하지 않는다.

- 미성년자는 18세 미만 나이나 미성년 신분을 명시한 인물, 이차성징 이전의 몸(아동의 머리 대 몸 비율과 체형)이 분명한 인물이다.
- 동안 얼굴, 큰 눈, 아이돌 같은 인상, 셀화, 작은 키, 마른 체형, 유행하는 옷차림 등 명시적이지 않은 모호한 신호나 문화적 취향은 미성년자 판단의 근거로 삼지 않는다.

## 구도

구도는 도상형과 장면형 두 가지다. 사용자가 구도를 지정하면 그대로 따르고, 지정하지 않으면 사용처에 따라 정한다. 사용처도 없으면 도상형으로 생성한다.

| 구도 | 모습 | 주 용도 | 프롬프트 순서 |
|---|---|---|---|
| 도상형 | 피사체를 화면 가운데에 배치하고 단색 배경을 사용함 | 본문 삽화, 장표 삽화, 사물 하나를 강조한 그림 | 피사체, 화풍, 색, `plain background` |
| 장면형 | 보편적인 소재 2-3개에 시간대 1개와 색 계열 1개를 추가함 | 배경 이미지, 배너, 표지, 간지, 슬라이드 배경, 풍경 그림 | 소재 조합, 시간대, 색, 화풍 |

- 도상형은 피사체를 화면에서 바로 알아볼 수 있는 결과를 채택한다.
- 장면형은 개별 사물보다 장면 전체의 분위기를 채택 기준으로 삼는다.
- 장면형의 소재 선택 방법과 시간대, 색 지정은 references/composition.md의 장면 구성 절을 따른다.

## 프리셋

프리셋은 모델과 고정 설정의 조합이다. 화풍은 프롬프트로 변경하고, 모델은 프리셋으로 변경한다.

| 프리셋 | 역할 | 적합한 화풍 | 생성 크기 | 첫 내려받기 |
|---|---|---|---|---|
| `dreamshaper-8-lcm` | 표준, 기본값 | 사진풍, 일러스트, 회화, 수채화 | 512x512 | 약 4.3GB |
| `sdxs` | 경량, 가장 빠름 | 일반 화풍, 묘사가 단순함 | 512x512 | 약 2.1GB |
| `tiny-sd` | 플랫 | 단색 면 플랫 벡터, 물감 번짐 수채화 | 384x384 | 약 1.1GB |
| `flux2-klein-4b` | 정밀, 가장 느림 | 지시 반영과 인체 형상이 가장 정확 | 384x512 | 약 5.2GB |

- 화풍과 품질 요구가 모두 없으면 표준을 사용한다.
- 표준은 플랫 벡터 키워드에서 형태가 무너진다. 플랫 벡터 요청에는 플랫이나 경량을 사용한다.
- 플랫은 인물이 주 피사체인 구도에서 머리가 잘리거나 액자 테두리가 함께 그려지는 경우가 잦다. 인물이 주 피사체면 표준이나 정밀을 사용한다.
- 경량은 사진풍 지시에도 일러스트처럼 생성되는 경향이 있다.

### 모델 선택 질의

아래 조건 중 하나라도 해당하면 생성 전 질의에 모델 선택을 포함한다. 해당하지 않으면 질의 없이 표준으로 진행한다. 사용자가 모델, 속도 우선, 품질 우선을 직접 언급했다면 질의 없이 그대로 따른다.

| 조건 | 선택지 |
|---|---|
| 한 번에 10장 이상 요청 | 표준, 경량 |
| 인물이 주 피사체(전신, 손이 보이는 구도 포함) | 표준, 정밀 |
| 플랫 벡터 또는 물감 번짐 질감 요청 | 플랫, 경량 |
| 환경 점검에서 자원이 부족함 | 실행 가능한 프리셋만 |

- 선택지마다 장당 예상 시간(예상치 표기), 첫 내려받기 용량, 화질과 화풍의 차이를 함께 기재한다.
- 초안, 시안, 반복 확인은 이미지 생성의 일반적인 형태이므로 모델 선택 질의나 경량 선택의 근거가 되지 않는다.
- 10장 기준은 표준 사용 시 전체 시간이 길어져 경량과의 차이가 체감되는 수량이다. 1-9장은 차이가 작다.

### 모델 고정

- 첫 생성에 사용한 모델은 같은 대화에서 사용자 허락이 있어야 변경한다. 모델을 변경하면 수 GB 내려받기, 장당 시간 증가, 화풍과 인상 변화가 수반된다. 이 변화는 모두 사용자가 예상한 비용과 결과를 벗어난다.
- 결함 대응은 선택한 모델 안에서 seed 변경, 가장자리 트림, 프롬프트 우회, 후처리, 구도 우회로 진행한다. 모델 교체는 자동 대응 수단에 포함하지 않는다.
- 모델 교체가 도움이 된다고 판단되면 재생성 상한에 도달했을 때 선택지 하나로 제시한다. 내려받기 용량, 장당 예상 시간, 달라지는 점을 함께 기재한다. 사용자가 선택하면 preflight.py를 `--preset`만 변경해 다시 실행한 뒤 교체한다.
- 실행이 불가능하면 원인(디스크 부족, 메모리 부족으로 인한 종료, 내려받기 오류)을 한 줄로 안내하고 실행 가능한 프리셋을 선택지로 제시한다. 기본 프리셋 이외의 캐시를 삭제해 디스크 부족이 해소되면 질의 없이 다시 시도한다. 실행 가능한 프리셋이 없으면 이유를 안내하고 작업을 중단한다.

## 생성 전 질의

첫 생성 전에 아래 표에서 해당하는 항목을 한 번에 질의한다. 후처리 설치 용량, 인상 변화, 질감 손실, 첫 프롬프트에서 원래 의도를 양보하는 정도는 사람마다 수용하는 범위가 달라 사용자가 선택한다. 결함이 생긴 뒤에 질의하면 자동 진행을 원하는 사용자의 작업이 중단되므로 질의는 생성 전에 진행한다.

| 항목 | 질의 조건 | 생략 조건 |
|---|---|---|
| 화질 보정 | 모든 요청 | 없음 |
| 가장자리 트림 | 모든 요청 | 없음 |
| 결함 후처리 | 인물 또는 정밀 사물이 등장함 | 없음 |
| 얼굴 복원 범위 | 인물이 등장함 | 없음 |
| 손가락 다시 그리기 | 인물이 등장함 | 결함 후처리가 우회만 자동 |
| 후보 생성 | 모든 요청 | 없음 |
| 후보 선택 | 표시 경로가 있음 | 후보 생성이 1배 |
| 여분 후보 보정 | 모든 요청 | 후보 생성이 1배, 또는 화질 보정이 안 함이면서 얼굴 복원 범위가 상시 이외 |
| 첫 프롬프트 우회 | 모든 요청 | 없음 |
| 재생성 상한 배수 | 모든 요청 | 없음 |
| 모델 선택 | 모델 선택 질의 조건에 해당함 | 사용자가 모델이나 속도, 품질 우선을 직접 언급함 |

- 인물이 한 명이라도 화면에 등장하면 크기, 비중, 화풍과 상관없이 인물이 등장하는 요청이다. 멀리 작게 등장하는 인물일수록 얼굴 결함이 심하므로 비중이 작다는 이유로 생략하지 않는다. 판단이 모호하면 인물이 등장하는 요청으로 간주한다.
- 정밀 사물은 자전거, 안경, 의자, 사다리, 건반처럼 부품의 연결 방식이 식별에 결정적인 사물이다.
- 사용자가 선택지를 직접 지정한 항목만 질의에서 제외한다. 권장 선택지가 있는 항목도 질의한다.
- "알아서 해줘", "기본값으로" 같은 위임 발화에는 권장 조합을 한 줄로 제시하고 확인을 받는다. 예: "1-b, 2-b, 3-a, 4-a, 5-a, 6-a, 9-a, 10-a로 진행할까요?" 비사진 화풍의 권장 조합은 얼굴 복원 미사용이다. 예: "1-b, 2-b, 3-a, 4-c, 5-a, 6-a, 9-a, 10-a로 진행할까요?" 권장 조합의 후보 생성은 1배다. 첫 프롬프트 우회는 기본값인 미사용이다. 재생성 상한 배수는 기본값인 1배다.
- 사물만 등장하는 요청도 화질 보정, 가장자리 트림, 후보 생성, 첫 프롬프트 우회는 질의한다.
- 질의 전에 전달 절의 표시 경로 판정을 수행한다. 표시 경로가 없으면 해당 절의 표에 따라 항목과 선택지를 줄인다.
- 후보 생성은 목표 장수보다 많은 후보를 한 번에 생성해 선택하는 방식이다. 결함 대응 1단계(같은 프롬프트로 seed만 변경해 다시 생성)를 생성 시점에 미리 수행하는 효과가 있다. 기본값 1배는 목표 장수만 생성한다.
- 후보 생성의 고정 배수 선택지에는 총 장수(목표 장수와 배수의 곱)와 probe.py 기준 예상 시간을 기재하고 예상치임을 명시한다. 자동 선택지에는 1배부터 권장 범위 상한인 3배까지의 총 장수 범위와 예상 시간 범위를 기재한다.
- 직접 입력은 정수 배수로 받는다. 목표 이미지마다 프롬프트가 다르면 총 장수만으로는 프롬프트별 장수가 정해지지 않기 때문이다.
- 여분 후보 보정의 선택지 문구에는 이 질의에서 선택할 수 있는 일괄 처리 이름만 기재한다. 사물만 등장하는 요청은 화질 보정만 기재한다.
- 모델 선택 질의의 10장 조건은 목표 장수로 판정한다. 배수는 같은 질의에서 답을 받으므로 모델 질의 여부를 배수 답변에 따라 정할 수 없다.
- 자동이 1배로 정해지면 후보 선택과 여분 후보 보정의 답은 사용하지 않는다.
- 첫 프롬프트 우회는 확산모델의 결함이 잦은 부분을 결함 확인 전인 첫 생성부터 피하는 방식이다. 인물, 동물, 사물, 건물, 장면 요소에 모두 적용된다. 기본값인 미사용은 원래 의도대로 먼저 생성한다. 결함이 보이면 가장자리 트림과 seed 변경을 먼저 적용하고, 그래도 결함이 남을 때만 결함 대응 2단계부터 우회한다. 최적화는 피사체와 장면을 유지하고 결함이 잦은 부분을 제거하거나 가리거나 화면 밖에 두는 연출만 추가한다. 최대 우회는 전달하려는 메시지와 사용처만 유지하고 구도 변경, 요소 제거, 피사체 교체까지 활용한다.
- 재생성 상한 배수는 결함 대응의 재생성 상한(references/defects.md)에 곱하는 배수다. 후보 생성의 배수와 구분하도록 항상 이 이름으로 부르고, 사용자 말이 어느 배수를 가리키는지 모호하면 한 줄로 확인한다. 항목 설명에는 실제 재생성 횟수가 적용되는 모델의 기본 상한에 배수를 곱해 정해진다는 점과 후보 생성을 늘리면 1단계 재생성 횟수가 줄어든다는 점을 안내한다. 모델과 후보 배수를 같은 질의에서 받으므로 선택지에는 배수만 기재한다. 답을 받으면 정해진 최대 재생성 횟수와 예상 시간(무제한은 3배 기준)을 생성 시작 전에 한 줄로 안내하고 확인 없이 진행한다. 요청에서 배수나 무제한을 직접 지정했으면 질의에서 제외하고 그 값을 기록한다.

질의 형식은 다음과 같다.

- 해당 항목만 선별해 1번부터 차례로 번호를 붙이고, 선택지는 a), b), c)로 표기한다. 모델 선택은 항상 마지막 번호에 배치한다.
- 조건부 항목(손가락 다시 그리기, 후보 선택, 여분 후보 보정)은 설명 첫 문장에 해당 조건을 실제 항목 번호로 기재한다.
- 일반 대화 텍스트의 번호 목록으로 작성하고 코드 블록과 표는 사용하지 않는다.
- 첫 줄에 답변 방법과 답변 예시를 기재한다.
- 첫 프롬프트 우회의 선택지 예시는 요청에서 결함이 잦은 부분에 맞춰 작성한다. 예: 자전거 요청이면 최적화는 바큇살 없는 미래형 전기자전거, 최대 우회는 바퀴가 없는 미래형 이동수단으로의 교체를 예로 든다.
- 사진풍이나 수채화 요청이면 화질 보정 항목에 경고 한 줄을 추가한다. 예: "사진풍과 수채화는 보정하면 피부 결과 종이 질감이 사라집니다."
- 플랫 벡터, 선화, 셀 채색 같은 비사진 화풍이면 얼굴 복원 범위의 미사용을 권장으로 표시하고 이유 한 줄을 추가한다. 예: "이 화풍에서는 복원한 얼굴만 사진처럼 바뀌어 그림체와 어울리지 않습니다." 얼굴 복원 도구는 실제 사진 얼굴로 학습되었기 때문이다.
- 얼굴 복원 범위 항목 설명에는 비정면 얼굴의 처리 방식을 한 줄로 안내한다. 예: "얼굴이 비스듬하거나 옆을 향한 인물은 복원으로 얼굴이 어색해질 수 있어 원본과 비교해 더 나은 쪽을 사용합니다." 얼굴 복원 도구는 정면 위주의 사진으로 학습되었고 얼굴을 정면 기준으로 정렬하기 때문이다.

인물이 등장하는 요청의 질의 예시:

> 생성 전에 아래 항목을 확인하겠습니다. 항목 번호와 선택지 기호로 답변해 주세요. (예: 1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c, 9-a, 10-a)
> 1. [화질 보정] 결함 대응과 트림을 마친 뒤 마지막에 한 번 적용합니다.
>    a) 안 함: 트림하거나 목표 크기로 확대할 때 흐림이 생깁니다
>    b) general: 대부분의 화풍에 적합합니다
>    c) flat: 플랫 벡터 전용입니다
> 2. [가장자리 트림] 손가락 같은 결함이 화면 가장자리에 접하거나 가까우면 다시 생성하기 전에 해당 가장자리를 소폭 잘라냅니다. 잘라낸 결함은 화면에서 완전히 사라지므로 이 경우 가장 확실한 방법입니다.
>    a) 미사용: 가장자리 결함도 다른 결함과 같은 대응 단계로 보정합니다
>    b) 동일 비율만: 화면 비율을 유지한 채 필요한 만큼 잘라낸 뒤 원래 크기로 복원합니다. 별도 확인 없이 적용하고 결과 전달 시 안내해 드립니다
>    c) 자유 비율까지: b로 해결되지 않는 경우 비율을 변경한 후보(예: 가로로 긴 구도)를 미리보기로 제시하고 선택하신 비율을 적용합니다
>    d) 자유 비율까지 자동: b로 해결되지 않는 경우 원래 구도에 가장 가까운 후보를 제가 선택해 적용하고 안내해 드립니다. 화면 비율이 변경될 수 있습니다
> 3. [결함 후처리] 인물의 얼굴, 옷, 착용물에 형태 결함이 생길 수 있습니다.
>    a) 후처리 자동: seed 변경과 프롬프트 우회 후에도 남은 결함을 얼굴 복원과 부위 다시 그리기로 자동 보정합니다 (설치 약 1.2GB, 부위 다시 그리기 사용 시 약 2.3GB 추가)
>    b) 우회만 자동: 설치 없이 seed 변경, 프롬프트 우회, 구도 우회로 진행합니다
>    c) 결함마다 질의: 후처리가 필요할 때마다 여쭙겠습니다
> 4. [얼굴 복원 범위] 얼굴이 비스듬하거나 옆을 향한 인물은 복원으로 얼굴이 어색해질 수 있어 원본과 비교해 더 나은 쪽을 사용합니다.
>    a) 결함 시에만: 얼굴 결함이 확인될 때 3번 방침에 따라 적용합니다
>    b) 상시: 결함 여부와 상관없이 모든 인물 이미지에 얼굴 복원을 적용합니다. 눈동자와 치아가 선명해집니다 (3번이 b여도 적용, 설치 약 1.2GB)
>    c) 미사용: 얼굴 복원을 설치하거나 사용하지 않습니다. 얼굴 결함은 seed 변경과 우회로 대응하고, 3번에서 선택한 옷과 착용물 다시 그리기는 그대로 유지합니다
> 5. [손가락 다시 그리기] 3번이 a나 c일 때만 해당합니다. 손가락 결함에는 효과가 낮으므로 가장자리 트림, seed 변경, 프롬프트 우회를 항상 먼저 시도합니다.
>    a) 미사용(권장): 남은 결함은 손이 화면 밖에 위치하는 구도로 대응합니다
>    b) 사용: 남은 결함에 한 번 적용하고 전후 비교 결과를 보여드립니다. 다른 사물과 겹치지 않은 손에만 적용하며 손 크기와 자세가 달라질 수 있습니다
> 6. [후보 생성] 목표 장수보다 많은 후보를 한 번에 생성한 뒤 선택합니다. 결함이 생긴 뒤 재생성을 기다리는 시간이 줄어듭니다. 장수와 시간은 목표 1장 기준이며 실행 환경 기준 예상치입니다.
>    a) 1배: 1장, 약 40초
>    b) 2배: 2장, 약 1분 20초
>    c) 3배: 3장, 약 2분
>    d) 자동: 1-3장, 약 40초-2분. 인물, 손, 군중처럼 결함이 잦은 요청에서만 배수를 늘리고 정한 배수를 생성 전에 안내해 드립니다
>    e) 직접 입력: 정수 배수로 입력해 주세요 (예: 6-e 4)
> 7. [후보 선택] 6번이 a가 아닐 때만 해당합니다.
>    a) 에이전트 선택: 결함이 없는 후보부터 차례로 목표 장수만큼 제가 선택해 마무리까지 진행합니다
>    b) 사용자 선택: 생성 직후 번호를 붙인 모아보기 한 장을 보여드리고, 번호로 선택하신 후보로 마무리합니다
> 8. [여분 후보 보정] 6번이 a가 아니고, 1번이 a가 아니거나 4번이 b일 때만 해당합니다. 선택하지 않은 후보(여분)에 화질 보정과 얼굴 상시 복원을 적용할지 정합니다. 결함 수리는 채택본에만 적용합니다.
>    a) 채택본만: 여분은 생성 원본 그대로 전달합니다. 원하시는 여분은 추후 별도로 마무리할 수 있습니다
>    b) 전 후보: 여분도 보정한 상태로 전달합니다. 후처리 시간이 후보 수에 비례해 늘어납니다
>    c) 자동: 작업 특성에 맞춰 a와 b 중 하나를 제가 정하고 생성 전에 안내해 드립니다
> 9. [첫 프롬프트 우회] 확산모델은 인물의 얼굴과 손가락, 사물의 부품 이음매, 건물 구조처럼 형태가 복잡한 부분에서 결함이 자주 발생합니다. 첫 생성부터 이런 부분을 피할지 정합니다. 우회 정도가 클수록 결함은 줄어들지만 요청하신 모습과 달라지는 부분이 늘어납니다.
>    a) 미사용(기본값): 요청하신 모습 그대로 먼저 생성합니다. 결함이 확인되면 트림과 seed 변경을 먼저 시도하고, 그래도 결함이 남으면 단계적으로 우회합니다
>    b) 최적화: 피사체와 장면은 그대로 유지하고 결함이 잦은 부분을 제거하거나 가리거나 화면 밖에 두는 연출을 처음부터 적용합니다. 이번 요청에서는 몸 옆으로 내린 손, 손이 화면 밖에 위치하는 샷, 선글라스, 장갑 같은 연출이 해당합니다
>    c) 최대 우회: 전달하려는 메시지와 사용처만 유지하고 결함이 잦은 요소를 최대한 피합니다. 옆모습이나 실루엣 같은 구도로 변경하거나 배경 군중 같은 요소를 제거하고, 필요하면 같은 의미를 전달하는 다른 사물이나 장면으로 교체합니다. 지정하신 피사체를 교체할 때는 생성 전에 확인을 받고, 구도를 변경하거나 요소를 제거할 때는 생성 전에 안내해 드립니다
> 10. [재생성 상한 배수] 결함이 남을 때 다시 생성하는 최대 횟수를 정합니다. 실제 횟수는 적용되는 모델의 기본 상한에 배수를 곱해 정해지며, 후보 생성을 늘리면 같은 프롬프트로 seed만 바꿔 다시 생성하는 횟수가 그만큼 줄어듭니다. 상한에 도달하면 가장 나은 결과를 보여드리고 다음 방향을 여쭙니다.
>    a) 1배(기본값)
>    b) 2배
>    c) 3배
>    d) 직접 입력: 정수 배수로 입력해 주세요 (예: 10-d 5)
>    e) 무제한(비권장): 3배까지 진행해도 결함이 남으면 여쭙지 않고 가장 나은 결과의 프롬프트로 seed만 바꿔 계속 생성합니다. 기본 상한 횟수만큼 시도할 때마다 진행 상황을 한 줄로 안내해 드립니다. 결함 후처리의 결함마다 질의, 가장자리 트림의 자유 비율 미리보기, 후보 선택의 사용자 선택을 고르셨다면 해당 질의에서는 답을 기다립니다

모델 선택 조건에 해당하면 마지막 번호로 이어서 기재한다. 예:

> 11. [모델 선택] 인물이 주 피사체이므로 모델에 따라 형태 결함 빈도가 달라집니다. 시간은 실행 환경 기준 예상치입니다.
>    a) 표준(DreamShaper 8 LCM): 장당 약 40초, 512px, 손과 옷 결함이 잦습니다
>    b) 정밀(FLUX.2 klein 4B): 장당 약 15분, 384x512, 형태가 가장 정확합니다. 첫 실행 시 약 5.2GB를 내려받습니다

예시의 시간은 형식 설명용 값이다. 실제 질의에는 probe.py의 예상치를 사용한다.

### 기록 전 읽기

후보 생성의 답이 1배가 아니면(자동 포함) 답을 받은 직후, preflight.py로 기록하기 전에 references/candidates.md를 읽는다. 후보 배수와 여분 후보 보정의 자동 판단, 후보 풀, 후보 채택, 후보 모드의 처리 범위, 여분 삭제가 이 문서에 수록되어 있다. 1배면 이 문서를 읽지 않고 진행한다.

첫 프롬프트 우회의 답이 최적화나 최대 우회면 답을 받은 직후, preflight.py로 기록하기 전에 references/defects.md를 읽는다. 첫 프롬프트 우회 절에 답변별 유지 요소와 사용 수단이 정리되어 있다. 최대 우회의 피사체 교체 확인 절차도 이 절에 있다. 피사체를 교체하면 `--subject`와 후보 배수 자동 판단이 달라질 수 있으므로 확인은 기록 전에 완료한다. 미사용이면 이 문서를 생성 후 점검 전에 읽는다.

### 답변 기록

답을 받으면 preflight.py로 출력 폴더에 preflight.json을 기록한다. 생성 스크립트는 이 파일이 없으면 종료 코드 2로 중단되고, preflight.py는 필요한 답이 누락되면 누락 항목을 나열한 뒤 종료 코드 2로 중단된다. 질의 없이 임의로 채운 값은 기록하지 않는다.

```
# 인물이 등장함, 답 "1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c, 9-b, 10-b", 자동 판단으로 3배와 전 후보를 결정함
PY scripts/preflight.py --out ./outputs --subject person --display available --enhance general --trim free --postfix auto --face-scope always --finger-inpaint off --candidates auto --candidates-resolved 3 --candidates-reason "전신과 손이 드러나는 인물 구도" --candidate-pick user --spare-finish auto --spare-finish-resolved all --spare-finish-reason "사용자 선택과 얼굴 상시 복원" --upfront-workaround optimize --regen-scale 2 --user-reply "1-b, 2-c, 3-a, 4-b, 5-a, 6-d, 7-b, 8-c, 9-b, 10-b"

# 사물만 등장함, 모델 선택 포함, 답 "1-b, 2-b, 3-a, 6-a, 7-a, 8-b"
PY scripts/preflight.py --out ./outputs --subject other --display available --enhance general --trim same --candidates 1 --upfront-workaround off --regen-scale 1 --preset sdxs --user-reply "1-b, 2-b, 3-a, 6-a, 7-a, 8-b"
```

- `--subject`는 인물이 등장하면 `person`, 인물 없이 정밀 사물이 등장하면 `precise-object`, 그 외는 `other`다.
- `--display`는 전달 절의 표시 경로 판정 결과다. 표시 경로가 있으면 `available`, 없으면 `none`이다. `none`에서 `--trim free`, `--finger-inpaint on`, `--candidate-pick user`는 종료 코드 2로 거부된다.
- `--candidates`는 정수 배수 또는 `auto`다. `auto`면 결정한 배수(1 이상의 정수)를 `--candidates-resolved`에, 근거 한 줄을 `--candidates-reason`에 기재한다.
- `--candidate-pick`은 에이전트 선택이 `auto`, 사용자 선택이 `user`다.
- `--spare-finish`는 채택본만이 `adopted`, 전 후보가 `all`, 자동이 `auto`다. `auto`면 결정한 값을 `--spare-finish-resolved`에, 근거 한 줄을 `--spare-finish-reason`에 기재한다.
- `--upfront-workaround`는 미사용이 `off`, 최적화가 `optimize`, 최대 우회가 `max`다.
- `--regen-scale`은 재생성 상한 배수다. 1배부터 3배는 `1`부터 `3`, 직접 입력은 입력한 정수, 무제한은 `unlimited`다.
- 후보 선택과 여분 후보 보정은 정해진 배수가 2 이상일 때만 필요하다. 사용하지 않는 항목은 null로 기록된다. 이후 단계는 `candidates_resolved`와 `spare_finish_resolved`에 기록된 값을 사용한다.
- `--user-reply`에는 사용자 답변을 그대로 기재한다.
- 같은 대화의 다음 생성은 같은 출력 폴더의 기록을 그대로 사용한다. 사용자가 선택을 변경하거나 인물 등장 여부가 달라지면 preflight.py를 다시 실행한다.
- 화풍이 사진풍이나 수채화로 새로 변경되면 화질 보정 항목만 다시 질의한다. 화풍이 사진풍과 비사진 화풍 사이에서 전환되면 얼굴 복원 범위 항목만 다시 질의한다.

## 프롬프트

- 프롬프트는 영어로 작성한다. 한국어 프롬프트는 명사 위주로만 해석되어 화풍과 장소 지시가 거의 반영되지 않는다.
- 피사체와 화풍 키워드를 앞에 배치한다. 수식어를 나열해 길이를 늘리지 않는다.
- 화풍은 기법 이름으로 기재한다. `watercolor illustration`, `flat vector illustration`, `digital painting`, `photorealistic`처럼 기법을 명시한 키워드가 `minimal editorial style` 같은 추상적인 표현보다 잘 반영된다.
- 색은 `muted blue and beige palette`처럼 계열을 직접 명시한다.
- 고유명사, 전문용어, 널리 쓰이지 않는 단어는 모델이 인식하지 못할 수 있다. 확산모델은 학습 이미지 설명에 자주 등장한 단어만 형태와 연결하기 때문이다. 판단 기준은 해당 단어가 일상적인 영어 사진 설명에 흔히 등장하는지 여부다.
- 이런 단어는 비슷한 흔한 사물로 대체하거나 생김새를 구성요소로 풀어 서술한다. 정확한 모습이 요청의 핵심이 아니면 대체하고, 고유한 모습이 핵심이면 풀어 서술한다. 예: 잘 알려지지 않은 자동차 모델명은 `a small white electric car`로 대체하고, 게임 속 갑옷 이름은 `golden plate armor`로 풀어 서술한다.
- 구성요소는 식별에 필요한 모양, 재질, 색 2-3개만 단순하게 기재한다. 세부 장식이 늘어나면 형태가 무너지기 쉽다. 길게 서술하면 SD 1.5 계열 프리셋의 77토큰 제한을 넘고 요소 누락도 늘어난다.
- 이미지 안에 글자를 포함하라는 지시는 작성하지 않는다.
- 작은따옴표(')는 명령행 인용 부호와 충돌하므로 사용하지 않는다.
- 표준, 경량, 플랫 프리셋은 SD 1.5 계열이다. 짧은 키워드형 영문이 잘 반영되고 긴 자연어 문장은 반영이 약하다. 텍스트 해석 범위가 77토큰이므로 초과한 문구는 오류 없이 무시된다. 시작과 끝 표지를 제외한 75토큰은 영어로 약 50단어다. generate.py가 무시된 문구를 경고로 출력하면 프롬프트를 줄여 다시 실행한다.
- 정밀 프리셋은 자연어 문장을 그대로 처리하며 77토큰 제한이 없다. 부정 프롬프트는 사용하지 않는다.
- 재현이 필요하면 seed를 고정하고, 다양한 결과가 필요하면 seed를 변경한다.
- 첫 프롬프트 우회가 미사용이면 결함을 피하려는 우회 지시(모자, 선글라스, 장갑 등)를 첫 생성 프롬프트에 포함하지 않는다. 우회 지시는 결함 대응 2단계에 진입한 뒤에 사용한다. 사용자가 처음부터 요청한 착용물은 원래 의도이므로 포함한다.
- 첫 프롬프트 우회가 최적화나 최대 우회면 references/defects.md의 첫 프롬프트 우회 절에 따라 첫 생성 프롬프트에 우회 연출을 포함한다.

## 생성

```
# 도상형, 기본 프리셋
PY scripts/generate.py --prompt "a brass compass on a desk, watercolor illustration, plain background" --out ./outputs --name compass

# 장면형 배너 1024x576, 세로로 선 피사체의 윗부분을 유지함
PY scripts/generate.py --prompt "a lighthouse on a rocky coast at sunrise, muted blue palette, watercolor illustration" --out ./outputs --name banner --width 1024 --height 576 --anchor-y 0.0

# 같은 프롬프트 4장, 모델을 한 번만 적재하고 seed를 1씩 증가시킴
PY scripts/generate.py --prompt "a stone staircase, digital painting, soft light, plain background" --out ./outputs --count 4

# 플랫 프리셋
PY scripts/generate.py --preset tiny-sd --prompt "flat vector illustration of a single lighthouse, muted blue palette, plain background" --out ./outputs --name lighthouse_flat
```

- 생성은 항상 정사각형으로 진행한다. 직사각형으로 생성하면 피사체가 긴 쪽으로 늘어나거나 눌린다. 다른 비율은 생성 후 잘라내는 방식으로 맞춘다.
- `--width`와 `--height`는 함께 지정한다. `--anchor-x`, `--anchor-y`는 잘라낼 기준점이며 0.0은 왼쪽과 위, 0.5는 가운데, 1.0은 오른쪽과 아래다. 사람, 탑, 등대처럼 세로로 선 피사체는 `--anchor-y 0.0`으로 윗부분을 유지한다. 하늘과 수평선 장면은 지평선이 아래 3분의 1 지점에 오도록 기준점을 정한다.
- 화질 보정을 선택한 경우 결과는 목표 비율만 맞춘 작업 크기로 저장된다(512px 생성의 1024x576 목표는 512x288). 목표 크기는 마무리 단계의 finalize.py가 생성한다.
- 화질 보정을 하지 않기로 한 경우 결과를 이 단계에서 목표 크기로 확대한다. 단순 확대는 화소 수만 늘리고 세부 묘사를 추가하지 않는다. 384px 플랫 프리셋 결과는 512px로 확대해 저장한다.
- 여러 장은 `--count`로 생성한다. 스크립트를 반복 호출하면 호출마다 모델 적재 시간이 추가된다.
- 같은 경로에 파일이 있으면 번호를 붙여 저장한다. 덮어써야 할 때만 `--overwrite`를 사용한다.
- stdout에는 장마다 경로, 프롬프트, seed, 프리셋, 정밀도, 크기, 소요 초가 JSON으로 출력된다.
- 비율을 변경해 잘라낸 결과는 열어서 피사체가 잘리지 않았는지 확인한다. 잘렸으면 같은 seed로 기준점만 변경해 다시 실행한다. 기준점 조정으로도 피사체가 모두 담기지 않으면 목표 비율에 맞는 구도(멀리 배치, 상반신 등)를 프롬프트에 추가해 다시 생성한다.
- 정밀 프리셋은 references/models.md의 정밀 프리셋 절에 따라 generate_klein.py로 실행한다.

정해진 배수가 2 이상이면 references/candidates.md의 후보 풀 절에 따라 후보를 생성한다.

## 점검

generate.py는 저장 직후 파일 크기(10KB 초과), 매직 바이트(JPEG `FFD8FF`, PNG `89504E47`), 픽셀 크기를 자동으로 확인한다. 종료 코드 7이 출력되면 육안 점검 전에 다시 생성한다.

### 점검 전 읽기

생성이 끝나면 점검과 얼굴 상시 복원보다 먼저 references/defects.md를 읽는다. 결함 판정 기준, 트림 우선 판정, 후보 채택 순서에 사용하는 대응 수단의 범위가 이 문서에 수록되어 있다. 결함을 발견한 뒤에 읽으면 해당 기준 없이 점검하게 된다.

결함 후처리가 후처리 자동이나 결함마다 질의이거나 얼굴 복원 범위가 상시면 references/postprocess.md도 함께 읽는다. 후처리로 해결되는 결함과 해결되지 않는 결함의 구분이 이 문서에 수록되어 있다. 그 밖의 답변에서는 후처리 도구를 사용하지 않는다.

- 같은 대화에서 읽은 내용이 남아 있으면 다시 읽지 않는다.

### 눈 점검

기계 점검을 통과하면 파일을 직접 열어 확인한다.

- 사용자가 지정한 피사체가 그대로 표현되었는가
- 프롬프트의 화풍과 색이 반영되었는가
- 사용할 크기로 축소했을 때 형태를 식별할 수 있는가
- 요청하지 않은 인물이 화면 가운데를 차지하지 않았는가
- 개수 결함(의도보다 많은 사물, 같은 피사체의 중복 등)이 없는가
- 인물과 동물의 신체 개수가 기준 개수(사람의 한 손 손가락 5개, 한 발 발가락 5개, 팔 2개, 다리 2개, 네발 동물의 다리 4개 등)와 일치하는가
- 인물의 얼굴에 얼굴 결함(두 눈의 크기 차이, 눈코입의 위치와 간격 왜곡, 얼굴 전체의 뭉개짐, 눈코입 일부의 누락 등)이 없는가
- 인물과 동물에 그 밖의 해부학적 결함(동물의 이목구비 왜곡, 손발 모양, 신체 왜곡 등)이 없는가
- 옷, 착용물, 사물, 건물에 연결 결함이나 구조 결함(끊긴 안경테, 사라진 끈, 엉킨 바큇살, 복잡한 기계 구조의 왜곡, 기둥 없이 지붕이 떠 있는 건물 형태의 왜곡 등)이 없는가
- 미성년자 보호 절에 해당하는 노출이나 성적 묘사가 없는가
- 발견한 결함이 화면의 네 변 중 하나에 접하거나 가까운가
- 도해 요청을 치환해 그리거나 최대 우회로 구도나 피사체를 변경한 경우 그림이 원래 메시지를 전달하는가
- 목록에 없더라도 확산모델의 전형적인 결함으로 보이는 부분, 시각적으로 어색한 부분, 사용자가 요청한 연출을 반영하지 못한 부분이 없는가
- 피사체가 가로나 세로로 눌려 있으면 정사각형으로 다시 생성한다

괄호 안은 예시다. 형태 이상은 실제 모습이나 요청한 화풍의 모습과 다르고 화면에 보이는 원인으로 설명되지 않는 부분이다. 화면에 보이는 원인은 가림(해당 부위 앞을 덮은 물체가 보이는 경우), 화면 가장자리, 얼굴 각도와 자세, 화풍이 의도한 생략과 과장이다. 해당 부위를 가리려는 의도가 없는 어둠, 흐림, 아웃포커스 등은 가림 원인으로 간주하지 않는다. 목록에 없는 형태 이상도 같은 기준에 따라 결함으로 간주한다. 판정이 모호하면 결함으로 간주한다. 화질 보정을 선택한 경우 위 점검은 작업 크기 결과물로 진행한다. 화질 보정을 마치면 references/defects.md의 화질 보정 후 재점검 절에 따라 4배 결과물에 위 점검을 다시 적용한다.

형태가 무너지기 쉬운 피사체는 전체 화면을 확인한 뒤 결함이 생기기 쉬운 부위(얼굴, 손발, 부품 이음매 등)를 확대해 다시 확인한다. 작게 표현된 부위는 전체 화면에서 결함이 잘 드러나지 않는다.

- 확대 이미지는 grid_measure.py에 영역을 지정해 생성한다. 결함이 생기기 쉬운 부위는 하나씩 별도로 확대하고, 해당 부위가 확대 화면을 거의 채우도록 영역을 지정한다. 영역은 대략적으로 지정할 수 있다. 여러 부위를 한 영역에 담으면 배율이 낮아져 손가락 같은 작은 결함이 전체 화면에서처럼 작게 보인다.
- 팔다리 수는 전체 화면에서 센다. 손가락과 발가락은 확대 화면에서 손발마다 하나씩 센다. 바닥, 허리, 등, 허벅지, 옷, 머리카락 등에 접촉하거나 밀착한 손은 손가락 경계가 접촉면과 섞여 결함을 놓치기 쉽다. 손가락과 발가락은 판정이 어려우므로, 손발이 드러난 경우에는 다섯 개가 모두 정확하게 표현된 결과가 이상적이다.
- 얼굴은 확대 화면에서 눈코입이 모두 있는지 확인한다. 눈코입의 위치, 간격, 크기, 좌우 균형은 defects.md의 배치 기준과 비교한다.
- 복부, 허리, 허벅지, 가슴 같은 큰 부위는 전체 화면에서 윤곽을 따라 확인한다. 윤곽이 끊기거나, 옷, 배경, 다른 신체 부위에 녹아 섞이거나, 자세와 맞지 않게 비틀린 부위는 신체 왜곡이다.
- 결함을 발견하면 확대 눈금을 트림과 부위 다시 그리기의 좌표 측정에도 활용한다.
- 채택하지 않기로 이미 정한 이미지는 확대하지 않는다.

점검 결과는 이미지마다 한 줄로 기록한다. 확인한 부위와 관찰한 상태를 기재하고, 결함이 없는 항목도 판정 근거를 기재한다. 신체 개수는 부위마다 센 숫자로 기재한다. 얼굴은 얼굴 방향, 눈코입의 유무, 배치 기준과 비교한 결과를 기재한다. 형태가 무너지기 쉬운 피사체는 기록 맨 앞의 확대 항목에 확대한 파일 이름을 기재한다. 채택할 이미지의 기록에 이 항목이 없으면 점검이 끝나지 않은 것으로 간주하고 확대부터 진행한다. 후보 모드의 채택 순위와 사용자 선택에서 안내하는 결함은 이 기록을 근거로 한다.

- 예: `reader-01: 확대(reader-01_face.png, reader-01_hand_l.png, reader-01_hand_r.png), 신체 개수 틀림(오른손 손가락 6, 아래 가장자리에 닿음), 얼굴 결함 없음(3/4 측면, 눈코입 모두 있음, 먼 쪽 눈은 각도만큼 좁음, 두 눈의 높이 같음, 코와 입은 돌아간 중심선 위), 해부학적 결함 없음(팔꿈치와 무릎 방향 자연스러움), 개수 결함 없음, 연결 결함 없음(안경테 이어짐)`
- 예: `reader-02: 확대(reader-02_face.png, reader-02_hand_l.png, reader-02_hand_r.png), 신체 개수 맞음(팔 2, 다리 2, 왼손 손가락 5, 오른손 손가락 3과 신문 뒤 2, 발가락은 신발에 가려짐), 얼굴 결함 없음(옆모습, 반대쪽 눈은 머리에 가려짐, 보이는 눈과 코와 입의 순서와 간격 자연스러움), 해부학적 결함 없음(신문을 쥔 손 모양 자연스러움), 개수 결함 없음, 연결 결함 있음(왼쪽 안경테 끊김, 가장자리에서 멂)`
- 해당하지 않는 항목(사물만 등장하는 이미지의 신체 개수, 얼굴 결함, 해부학적 결함 등)은 기재하지 않는다.

정해진 배수가 2 이상이면 references/candidates.md의 후보 채택 절에 따라 목표 장수만큼 채택한다. 기존 항목의 답은 같은 문서의 후보 모드의 처리 범위 절에 따라 적용한다.

## 결함 대응

결함을 발견하면 references/defects.md의 순서를 따른다. 전체 순서는 다음과 같다.

1. 트림 우선 판정: 결함이 가장자리에 접하거나 가깝고 그 결함 외에는 다시 생성할 이유가 없는 경우다. 트림 답변이 동일 비율만, 자유 비율까지, 자유 비율까지 자동 중 하나라면 재생성보다 가장자리 트림을 먼저 실행한다.
2. 일반 결함: 화풍, 색, 개수, 배경, 구도 문제는 프롬프트 수정과 seed 변경으로 해결한다.
3. 형태가 무너지기 쉬운 피사체(인물, 동물, 정밀 사물, 배경 군중): 대응 1단계 seed 변경, 2단계 프롬프트 우회, 3단계 후처리, 4단계 구도 우회 순으로 진행한다.
4. 재생성 상한 배수를 적용한 상한에 도달하면 가장 나은 결과를 결함 위치와 함께 제시하고 다음 방향을 질의한다. 무제한이면 질의 없이 반복 단계로 전환한다. 가장 나은 결과의 정의, 배수 산정, 무제한 운영은 references/defects.md의 재생성 상한 절에 있다.

2단계와 4단계는 첫 프롬프트 우회에 사용하지 않은 우회 수단 중에서 선택한다. 세부 규칙은 references/defects.md의 첫 프롬프트 우회 절에 있다.

정해진 배수가 2 이상이면 후보 풀 교체 횟수를 형태 결함 대응 1단계의 상한에서 뺀다. 후보 풀이 소진되면 1단계의 남은 횟수만큼 재생성한 뒤 2단계로 진행한다. 일반 결함은 후보 풀 교체 횟수를 seed 변경 상한에서 뺀다. 세부 규칙과 재생성 상한은 references/defects.md에 있다.

후처리 도구(얼굴 복원, 부위 다시 그리기, 손가락 다시 그리기)의 선택, 강도, 설치, 정리는 references/postprocess.md에 있다.

## 화질 보정

화질 보정은 4배 초해상도로 확대한 뒤 목표 크기로 축소하는 마무리 단계다. 생성 크기가 512px 이하이므로 트림, 비정사각 규격, 목표 크기에 맞추려면 확대가 필요하다. 단순 확대는 이미지가 흐려지므로 모든 확대를 이 단계로 대체한다.

| 선택 | 적합한 대상 | 부작용 |
|---|---|---|
| 안 함 | 질감 보존이 우선인 요청 | 원본의 흐림이 남는다 |
| general | 화풍 전반, 인물 포함 | 사진풍과 수채화에서 피부 결과 종이 질감이 사라진다 |
| flat | 플랫 벡터 배경 | 인물에서 밀랍 같은 질감, 콧구멍 경계 과장, 머리카락 뭉침이 생긴다 |

- 결함 대응과 트림을 모두 마친 채택본에 한 번만 적용한다. 생성 직후에 적용하면 트림 후 다시 확대하거나 두 번 적용하게 되어 밀랍 같은 질감이 누적된다. 얼굴 복원과 부위 다시 그리기도 보정 전 크기에서 동작하도록 설정되어 있다. 폐기되는 시도에는 적용하지 않으므로 추가 시간은 채택본 한 장 분량이다. 화질 보정 후 재점검으로 채택본을 수정하면 수정한 채택본을 입력으로 한 번 더 실행한다.
- 후보 모드에서는 여분 후보 보정의 정해진 값을 따른다. 전 후보면 여분에도 한 장에 한 번씩 적용하므로 추가 시간이 후보 수에 비례해 늘어난다. 여분은 결함 수리를 거치지 않으므로 채택 직후 출력 폴더에서 적용한다.
- 질감 손실은 후처리 고유의 특성이므로 프롬프트나 seed로 되돌릴 수 없다.
- 초해상도는 이목구비 결함을 보정하지 못한다. 얼굴 결함은 결함 대응 절차로 보정한다.
- 첫 사용 시 가중치(수 MB)를 GitHub에서 내려받고 SHA-256으로 확인한다. 추가 설치는 필요하지 않다.
- 목표 크기는 입력의 4배 이내로 지정한다. 초과분은 단순 확대로 처리된다.
- 생성 프로세스가 끝난 뒤 별도로 실행하므로 메모리 사용이 겹치지 않는다.

```
PY scripts/finalize.py ./outputs/banner_trim.png ./outputs/banner_final.png --size 1024x576 --x4-out ./outputs/banner_x4.png
```

- `--size`를 지정하지 않으면 768x768로 생성한다. 보정 방식은 preflight.json의 답을 따른다.
- 트림에서 비율을 변경한 경우 edge_trim.py가 출력한 `target=WxH`를 `--size`에 그대로 입력한다. 원래 목표 크기를 입력하면 원래 비율로 다시 잘려 보존한 부위가 잘린다.
- `--x4-out`은 축소 전 4배 결과물을 화질 보정 후 재점검용으로 저장한다. 재점검 대상은 채택본이므로 채택본에만 지정한다.
- 실행 직후 전달 전에 references/defects.md의 화질 보정 후 재점검 절에 따라 4배 결과물을 점검한다.

## 전달

- 파일 이름은 내용을 알 수 있도록 영문 소문자와 밑줄로 작성한다. 예: `lighthouse_flat_vector.png`
- 실행 환경에 파일 제시 수단이 있으면 해당 수단으로 전달하고, 없으면 절대 경로를 안내한다.
- 재현 정보로 프롬프트, seed, 프리셋, 크기, 화질 보정 선택을 함께 기록한다.
- 첫 프롬프트 우회를 사용한 경우 재현 정보에 해당 선택을 추가하고, 적용한 우회 연출과 원 요청에서 달라진 요소를 함께 안내한다.
- 후보 모드에서는 채택본과 함께 후보 폴더 경로와 모아보기를 제시한다. 재현 정보에 후보별 seed, 정해진 배수, 여분 후보 보정 선택을 추가한다. 자동으로 정한 배수와 여분 후보 보정 선택은 근거를 함께 기재한다.
- 트림한 결과는 트림 사실, 절단선이 지나는 부위, 잘린 비율(자유 비율이면 채택 비율과 남은 면적)을 함께 안내한다.
- 프롬프트에서 모델이 인식하지 못할 단어를 대체하거나 풀어 서술한 경우 원래 단어와 변경한 표현을 함께 안내한다.
- JPEG가 필요하면 `--format jpg`로 생성하거나 PNG를 변환한다.

정해진 배수가 2 이상이면 여분 삭제는 references/candidates.md의 여분 삭제 절을 따른다.

### 표시 경로 판정

사용자에게 이미지를 제시하는 모든 지점은 이 판정을 따른다. 판정은 생성 전 질의 단계에서 한 번 수행한다. 에이전트가 보유한 도구와 실행 위치를 확인해 아래 세 유형 중 하나로 정한다.

| 표시 경로 | 판정 기준 | `--display` |
|---|---|---|
| 파일 제시 도구 | 실행 환경에 사용자 화면에 파일을 표시하는 도구가 있음 | `available` |
| 공유 파일 시스템 | 에이전트가 사용자의 컴퓨터에서 실행되어, 절대 경로를 안내하면 사용자가 열 수 있음 | `available` |
| 표시 경로 없음 | 제시 도구가 없는 원격 실행 환경처럼, 절대 경로를 안내해도 사용자가 열 수 없음 | `none` |

표시 경로가 없으면 지점마다 아래와 같이 처리한다.

| 이미지 표시 지점 | 표시 경로가 없을 때 |
|---|---|
| 후보 선택의 사용자 선택 | 항목을 질의하지 않고 에이전트 선택으로 진행한다 |
| 가장자리 트림의 자유 비율까지 | 선택지에서 제외한다 |
| 손가락 다시 그리기의 사용 | 선택지에서 제외한다. 전후 비교 확인이 필요하기 때문이다 |
| 비사진 화풍의 얼굴 복원 전후 비교 | 화풍과 어울리는 안을 직접 선택하고 전달할 때 이유를 한 줄로 안내한다 |
| 재생성 상한 도달 | 결함 위치를 텍스트로 설명하고 다음 방향을 질의한다 |

- 선택지를 제외한 항목은 남은 선택지에 a)부터 차례로 기호를 다시 붙인다. 손가락 다시 그리기는 미사용만 남아도 질의하고 답을 기록한다.

## 자원과 캐시

- 디스크와 메모리는 내려받기와 실행 직전마다 새로 확인한다. 모델, 얼굴 복원, 부위 다시 그리기, 화질 보정이 각각 가중치를 내려받으므로 같은 대화 안에서도 여유 공간이 계속 변한다.
- 생성, 얼굴 복원, 부위 다시 그리기, 화질 보정은 각각 별도 프로세스로 하나씩 실행한다. 앞 프로세스의 종료를 확인한 뒤 다음 프로세스를 실행한다. 두 프로세스를 동시에 실행하면 메모리 부족으로 종료될 수 있다.
- 메모리 부족으로 종료되면 남은 프로세스를 정리하고 한 번 다시 시도한다. 그래도 부족하면 실행 가능한 더 가벼운 프리셋을 선택지로 제시한다.
- 스킬은 캐시 폴더 안의 파일만 삭제한다. 캐시 폴더 밖의 파일과 다른 프로그램의 모델 캐시는 변경하지 않는다. 예외는 사용자가 삭제를 요청한 후보 모드의 여분 파일이다(references/candidates.md의 여분 삭제 절).
- 디스크가 부족하면 사용을 마친 후처리 가중치, 기본 프리셋 이외의 프리셋 순서로 삭제한다. 같은 대화에서 다시 사용할 파일은 다시 내려받는 시간이 소요되므로 작업이 끝날 때까지 유지한다.
- 삭제한 대상과 삭제 후의 여유 공간을 기록한다.
- 세션 종료 시 파일이 삭제되는 실행 환경에서는 다음 세션에서 가상환경과 모델을 다시 준비한다.

```
PY scripts/cache.py list
PY scripts/cache.py delete sdxs
PY scripts/cache.py delete all    # 가상환경을 제외한 캐시 전체
```

## 실패 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 종료 코드 2, preflight.json 없음 | 생성 전 질의를 진행하지 않음 | 해당 항목을 질의하고 preflight.py로 기록한다 |
| 종료 코드 2, 인자 오류 | 인자 누락이나 범위 밖 값 | 메시지에 따라 인자를 수정한다. BOX_TOO_LARGE는 상자를 분할해 실행한다 |
| 종료 코드 3 | 가중치 내려받기 실패 | 다시 실행한다. 반복되면 화질 보정을 비활성화하고 사용자에게 안내한다 |
| 종료 코드 4 | 의존성 미설치 | 환경 준비 또는 후처리 설치 단계로 돌아간다 |
| 종료 코드 6 | 메모리나 디스크 부족 | 디스크 부족은 cache.py로 기본 프리셋 이외의 캐시를 삭제한 뒤 다시 시도한다. 메모리 부족은 모델 고정 절의 실행 불가 절차를 따른다 |
| 종료 코드 7 | 산출물 점검 실패 | seed를 변경해 다시 생성한다 |
| 종료 코드 8 | 가중치 해시 불일치, 손상 파일은 자동 삭제됨 | 다시 실행해 새로 내려받는다. 반복되면 해당 기능을 비활성화하고 안내한다 |
| 종료 코드 9 | 정밀 프리셋을 지원하지 않는 운영체제 | 다른 프리셋을 선택지로 제시한다 |
| 화풍 지시 미반영 | 한국어 프롬프트, 추상적인 화풍 표현 | 영문으로 다시 작성하고 기법 이름을 앞에 배치한다 |
| 형태가 뭉개짐 | 프리셋 설정을 변경함 | 스텝 수, guidance, 스케줄러를 스크립트 기본값으로 되돌린다 |
| 글자, 개수, 상태 지시 미반영 | 확산모델의 한계 | 해당 지시를 삭제하고 편집 도구에서 보완한다 |
| 사용자가 지정한 사물이 표현되지 않음 | 지정 피사체를 메시지 요청으로 잘못 분류함 | 지정 피사체로 다시 분류하고 해당 사물로 다시 생성한다 |
| 사용자가 지정한 사물이 다른 모습으로 표현됨 | 모델이 인식하지 못하는 이름(고유명사, 전문용어, 드문 단어) | 프롬프트 절에 따라 비슷한 흔한 사물로 대체하거나 구성요소로 풀어 서술한다 |
| gfpgan 설치 중 `KeyError: '__version__'` | 최신 Python에서 basicsr의 setup.py가 실패함(Python 3.13과 basicsr 1.4.2 조합에서 확인) | references/postprocess.md 설치 절의 우회 절차를 따른다 |
| gfpgan import 시 functional_tensor 오류 | torchvision에서 삭제된 모듈을 basicsr가 참조 | `PY scripts/patch_basicsr.py` 실행 후 다시 시도한다 |
