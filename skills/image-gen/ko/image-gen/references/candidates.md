# 후보 모드

후보 모드의 절차를 정리한 문서다. 생성 전 질의에서 후보 생성의 답이 1배가 아니면(자동 포함) 답을 받은 직후, preflight.py로 기록하기 전에 읽는다. 자동 판단은 기록 전에 완료되어야 하고, 생성 이후의 후보 처리도 이 문서를 따르기 때문이다. 질의 항목과 preflight.py 인자는 SKILL.md의 생성 전 질의 절에 있다. 결함 대응과 후처리의 후보 모드 규칙은 defects.md와 postprocess.md에 있다.

## 후보 배수 자동 판단

후보 생성의 답이 자동이면 답을 받은 뒤 preflight.py로 기록하기 전에 배수를 정한다. 기준값은 1배다. 아래 근거가 있을 때만 배수를 높인다.

- 주 피사체가 형태가 무너지기 쉬운 피사체(인물, 동물, 정밀 사물)다.
- 인물의 손이나 전신이 화면에 드러나는 구도다.
- 여러 인물이나 배경 군중이 등장하는 장면이다.

아래 경우는 1배를 권장한다.

- 정밀 프리셋을 사용한다. 장당 시간이 가장 길고 형태 정확도가 가장 높다.
- 형태가 무너지기 쉬운 피사체가 없는 사물 도상이나 풍경 장면이다.

배수는 아래 권장 기준에 맞춰 정한다.

- 근거가 하나면 2배를 검토한다. 근거가 여럿이면 3배를 검토한다.
- 권장 범위는 1-3배다.
- 정한 배수, 근거 한 줄, 총 장수, 예상 시간을 생성 시작 전에 안내한다. 안내 후 확인을 받지 않고 진행한다. 트림의 자유 비율까지 자동과 같은 방식이다.

## 여분 후보 보정 자동 판단

여분 후보 보정의 답이 자동이면 배수가 정해진 뒤 preflight.py로 기록하기 전에 정한다. 기준값은 a) 채택본만이다. 채택본만은 생성 원본이 남아 추후 여분을 별도로 마무리할 수 있으므로 되돌릴 수 있는 선택이다. 전 후보는 후처리 시간을 미리 소비하므로 되돌릴 수 없는 선택이다.

아래 경우에만 b) 전 후보로 정한다.

- 후보 선택이 사용자 선택이고 얼굴 복원 범위가 상시다. 복원 전후의 얼굴 차이가 커서, 모아보기를 복원본으로 생성해야 사용자가 최종 모습을 기준으로 선택할 수 있다.
- 요청에 여러 안을 모두 받으려는 의도가 드러나 있다.

- 화질 보정만 해당하는 경우는 a를 유지한다. 화질 보정은 주로 선명도와 크기를 변경하므로 구도와 표정 비교에 영향이 적다.
- 정한 선택과 근거 한 줄을 생성 시작 전에 안내한다. 안내 후 확인을 받지 않고 진행한다.

## 후보 풀

정해진 배수가 2 이상이면 목표 장수와 배수의 곱만큼 후보를 생성한다. 이 후보 집합을 후보 풀이라 한다.

```
# 같은 프롬프트로 목표 2장, 후보 2배
PY scripts/generate.py --prompt "a red bicycle leaning against a brick wall, side view, watercolor illustration" --out ./outputs --name bicycle --count 4

# 정밀 프리셋, 후보 2배, seed와 파일 이름을 변경해 한 장씩
PY scripts/generate_klein.py "an elderly man reading a newspaper on a park bench, photorealistic" ./outputs/reader-01.png --seed 42
PY scripts/generate_klein.py "an elderly man reading a newspaper on a park bench, photorealistic" ./outputs/reader-02.png --seed 43
```

- 프롬프트가 같은 목표 이미지는 `--count`에 목표 장수와 배수의 곱을 지정해 한 번에 실행한다. 목표 이미지마다 프롬프트가 다르면 프롬프트마다 `--count`에 배수를 지정한다.
- 정밀 프리셋은 한 번에 한 장만 생성한다. 후보는 seed를 1씩 증가시키고 파일 이름을 변경해 장마다 별도로 실행한다. 앞 실행이 끝난 뒤 다음 실행을 시작한다.
- 후보는 출력 폴더에 생성한다. 생성 스크립트와 finalize.py는 출력 폴더의 preflight.json을 읽으므로, 하위 폴더에 저장하면 종료 코드 2로 중단된다. 여분은 채택 후 `candidates` 폴더로 이동한다(아래 후보 채택 절).

## 후보 채택

정해진 배수가 2 이상이면 후보 풀 전체를 점검한 뒤 목표 장수만큼 채택한다.

1. 모든 후보를 원본 파일로 SKILL.md 눈 점검 절의 항목에 따라 점검한다. 얼굴 복원 범위가 상시면 여분 후보 보정의 정해진 값을 따른다. 전 후보면 모든 후보에 얼굴 복원을 한 번씩 적용한 뒤 복원본으로 점검한다. 채택본만이면 원본으로 점검하고, 채택 후 채택본에만 복원한 다음 복원본으로 판정한다. 3/4 측면이나 옆모습 얼굴은 복원할 때마다 postprocess.md의 비정면 얼굴 규칙에 따라 원본과 비교한다. 원본을 채택한 후보는 이후 단계에서 복원본 대신 원본을 사용한다.
2. 모든 후보로 모아보기를 생성한다. 모든 후보에 얼굴 복원을 적용했으면 복원본으로 생성하고, 그 밖에는 생성 원본으로 생성한다. 화질 보정은 채택 후에 적용하므로 모아보기에 반영하지 않는다.
3. 후보 선택의 답에 따라 채택한다.
4. 여분 후보 보정이 전 후보이고 화질 보정을 선택한 경우 여분마다 화질 보정을 한 번 적용한다. 입력은 복원본이 있으면 복원본, 없으면 생성 원본이다. finalize.py는 출력 폴더의 preflight.json을 읽으므로 이동하기 전에 출력 폴더에서 적용한다. 사용자가 여분 삭제를 요청했으면 건너뛴다.
5. 여분의 생성 원본과 보정본을 출력 폴더 안의 `candidates` 폴더로 이동한다. 채택본은 출력 폴더에 유지하고 결함 대응, 트림, 화질 보정으로 마무리한다.

```
PY scripts/contact_sheet.py ./outputs/bicycle-01.png ./outputs/bicycle-02.png ./outputs/bicycle-03.png ./outputs/bicycle-04.png --out ./outputs/bicycle_sheet.png
PY scripts/contact_sheet.py "./outputs/reader-0?_face.png" --out ./outputs/reader_sheet.png   # 복원본, 와일드카드는 스크립트가 확장한다
```

- 모아보기는 입력 순서대로 1번부터 번호를 붙인다. stdout에는 번호와 파일의 대응이 JSON으로 출력된다.
- 모아보기는 구도와 표정을 선택하는 용도다. 작은 결함은 원본 후보 파일로 판정한다.
- 에이전트 선택은 아래 채택 순서에 따라 목표 장수만큼 채택하고 마무리까지 진행한다. 채택한 후보, 순위, 근거를 기록한다.
- 사용자 선택은 생성 직후 모아보기를 제시하고 사용자가 번호로 선택하도록 한다. 후보마다 발견한 결함을 한 줄씩 함께 안내한다. 여분 삭제 여부도 같은 답변에서 받도록 한 줄로 질의한다(아래 여분 삭제 절). 선택된 후보로 결함 대응과 마무리를 진행한다.
- 사용자가 선택한 후보에 해결 수단이 없는 결함이 있으면, 해당 결함을 안내하고 남은 후보에서 다시 선택할지 결함 대응 2단계로 진행할지 질의한다.
- 표시 경로가 없으면 사용자 선택을 질의하지 않고 에이전트 선택으로 진행한다.

에이전트 채택 순서는 다음과 같다.

1. 결함이 없는 후보
2. 트림으로 해결되는 결함만 있는 후보(트림 답이 미사용 이외). 동일 비율 트림으로 해결되는 후보가 자유 비율 트림 후보보다 우선한다.
3. 후처리로 해결되는 결함만 있는 후보(결함 후처리 답이 후처리 자동이나 결함마다 질의). 얼굴 상시 복원으로 해결되는 얼굴 결함은 결함 후처리 답과 상관없이 이 순위에 포함된다.

- 같은 순위 안에서는 원 요청의 피사체, 구도, 화풍에 가장 가까운 후보를 선택한다.
- 해결 수단이 없는 결함 후보는 채택하지 않는다. 다시 생성해야 해결되는 일반 결함(화풍, 색, 개수 등)도 여기에 해당한다.
- 목표 장수에 미달한 부분은 결함 대응 절차로 채운다. 형태가 무너지기 쉬운 피사체는 1단계 재생성 없이 2단계부터 진행한다(defects.md).

## 후보 모드의 처리 범위

기존 항목의 답은 후보 모드에서 아래와 같이 적용한다.

| 기존 항목 | 후보 모드 동작 |
|---|---|
| 화질 보정 | 여분 후보 보정의 정해진 값에 따라 채택본에만, 또는 모든 후보에 한 번씩 적용한다 |
| 가장자리 트림 | 채택한 후보의 결함에만 적용한다. 미사용이면 채택 순서의 2순위가 없다 |
| 결함 후처리 | 후처리 자동은 채택 순서의 3순위로 사용한다. 우회만 자동은 후처리가 있어야 해결되는 후보를 해결 수단이 없는 후보로 간주한다. 결함마다 질의는 앞 순위 후보가 부족할 때만 질의한다 |
| 얼굴 복원 범위 | 상시는 여분 후보 보정의 정해진 값을 따른다. 결함 시에만은 결함 후처리 규칙을 따른다. 미사용은 해당 사항이 없다 |
| 손가락 다시 그리기 | 채택한 후보에만 적용한다 |

- 결함별 수리(트림, 결함 시 얼굴 복원, 부위 다시 그리기, 손가락 다시 그리기 등)는 답과 상관없이 채택본에만 적용한다. 결함 수리는 후보마다 판정과 사용자 확인이 필요하므로, 여분까지 적용하면 질의와 시간이 후보 수에 비례해 늘어난다.
- 얼굴 상시 복원은 후보마다 한 번만 적용한다.
- 사용자가 여분 일부를 원하면 해당 후보의 생성 원본을 출력 폴더로 이동해 채택본과 같은 수리와 마무리 절차를 추가로 실행한다. 화질 보정은 한 번만 적용하므로 생성 원본에서 다시 시작한다.

## 여분 삭제

여분은 기본적으로 보관한다. 삭제는 되돌릴 수 없으므로 사용자가 후보를 확인한 뒤 삭제를 요청한 경우에만 삭제한다. 이 질의는 이미 사용자 답변을 기다리는 지점에서만 진행하므로 자동 진행을 중단시키지 않는다.

- 삭제 여부는 한 번만 질의한다. 사용자 선택은 모아보기를 제시할 때, 에이전트 선택은 전달할 때 한 줄로 질의한다.
- 삭제는 결함 대응과 마무리를 마친 뒤 전달 단계에서 진행한다. 그 전에는 후보 풀 교체에 여분이 필요하다.
- 삭제 대상은 이번 요청에서 생성한 여분 파일(생성 원본, 복원본, 보정본)로 제한한다. 채택본과 모아보기는 유지한다. 후보 폴더가 비면 폴더도 삭제한다.
- 삭제한 파일 이름은 전달할 때 안내한다.
